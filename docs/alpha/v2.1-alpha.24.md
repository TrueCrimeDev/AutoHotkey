# AutoHotkey v2.1-alpha.24

**Released:** 2026-03-29
**Previous:** [v2.1-alpha.23](./v2.1-alpha.23.md)
**Next:** [v2.1-alpha.25](./v2.1-alpha.25.md)
**Upstream tag:** [`v2.1-alpha.24`](https://github.com/AutoHotkey/AutoHotkey/tree/v2.1-alpha.24)

## Overview

Alpha.24 focuses on the Struct/type system and module infrastructure. The headline
additions are typed `CallbackCreate` parameters, union-layout support via `DefineProp`
`Offset`, and wildcard module re-exports (`#Import Export X {*}`). Several memory-safety
bugs in the Struct subsystem are also resolved: circular references that blocked garbage
collection, undefined behaviour in nested-struct teardown, and empty-Struct misuse in
`DllCall`.

---

## New features

### CallbackCreate — typed parameter arrays

`CallbackCreate` previously accepted only a plain integer as its third argument
(`ParamCount`). It now also accepts an **Array of type classes**. Every element before
the last describes a parameter type; the last element is the return type. This lets the
runtime perform correct type conversions for values (such as floats or structs) that
cannot be inferred from a raw pointer-sized stack slot.

```autohotkey
; Classic form — integer param count, all params treated as pointer-sized integers.
AddInts(a, b) => a + b

cbClassic := CallbackCreate(AddInts, , 2)
result := DllCall(cbClassic, "Int", 15, "Int", 27, "Int")  ; 42
CallbackFree(cbClassic)

; Typed form — [Param1Type, Param2Type, ..., ReturnType]
cbTyped := CallbackCreate(AddInts, , [Int32, Int32, Int32])
result := DllCall(cbTyped, "Int", 100, "Int", 200, "Int")  ; 300
CallbackFree(cbTyped)

; Floats — this is where typed params are essential.
; Without types, float bit patterns are misread as integers.
AddFloats(a, b) => a + b

cbFloat := CallbackCreate(AddFloats, , [Float64, Float64, Float64])
result := DllCall(cbFloat, "Double", 1.5, "Double", 2.7, "Double")  ; 4.2
CallbackFree(cbFloat)

; Mixed types
Multiply(x, factor) => x * factor

cbMix := CallbackCreate(Multiply, , [Float64, Int32, Float64])
result := DllCall(cbMix, "Double", 3.14, "Int", 3, "Double")  ; 9.42
CallbackFree(cbMix)
```

The integer (`ParamCount`) form remains fully supported and unchanged.

### DefineProp — Offset sub-parameter for union-like fields

`DefineProp` now accepts an `Offset` key in its descriptor object. Setting multiple
fields to the same byte offset creates a **C-style union**: all such fields share the
same memory location.

`Offset` may be:
- An **integer** — explicit byte position within the struct.
- A **string** matching another field name — the field is placed at that field's offset
  (useful when you want to alias a sub-range by name).

```autohotkey
; VARIANT-style union: vtype at offset 0, all value fields overlap at offset 8.
Struct Variant {
    vtype: u16
}
DefineProp(Variant.Prototype, "intVal", {Type: Int32,   Offset: 8})
DefineProp(Variant.Prototype, "fltVal", {Type: Float64, Offset: 8})
DefineProp(Variant.Prototype, "ptrVal", {Type: IntPtr,  Offset: 8})

v := Variant()
v.vtype  := 3   ; VT_I4
v.intVal := 42
MsgBox("intVal=" . v.intVal)   ; 42

v.vtype  := 5   ; VT_R8
v.fltVal := 3.14159
MsgBox(Format("fltVal={:.5f}", v.fltVal))

; RGBA color: one u32 word + four overlapping byte channels.
Struct Color {
    rgba: u32
}
DefineProp(Color.Prototype, "r", {Type: UInt8, Offset: 0})
DefineProp(Color.Prototype, "g", {Type: UInt8, Offset: 1})
DefineProp(Color.Prototype, "b", {Type: UInt8, Offset: 2})
DefineProp(Color.Prototype, "a", {Type: UInt8, Offset: 3})

c := Color()
c.rgba := 0xFF8040C0
MsgBox(Format("r=0x{:02X} g=0x{:02X} b=0x{:02X} a=0x{:02X}", c.r, c.g, c.b, c.a))

; Write individual channels, then read back as u32.
c.r := 0x00, c.g := 0xFF, c.b := 0x00, c.a := 0xFF
MsgBox(Format("rgba=0x{:08X}", c.rgba))

; Named offset: "full" sits at the same offset as "lo".
Struct Register {
    lo: u16
    hi: u16
}
DefineProp(Register.Prototype, "full", {Type: UInt32, Offset: "lo"})

reg := Register()
reg.full := 0xDEADBEEF
MsgBox(Format("lo=0x{:04X}  hi=0x{:04X}", reg.lo, reg.hi))
```

### `#Import Export X {*}` — wildcard re-export

The module system gains a **wildcard re-export** form:

```autohotkey
#Import Export ModuleName {*}
```

This re-exports every public symbol from `ModuleName` as if it were defined in the
current module. It enables barrel / facade modules that aggregate sub-module exports
without listing each name individually.

```autohotkey
; math/vector.ahk
#Module Math.Vector
export Vec2(x, y)   => {x: x, y: y}
export Vec3(x, y, z) => {x: x, y: y, z: z}

; math/matrix.ahk
#Module Math.Matrix
export Mat4() => {}   ; ...

; math/index.ahk  — facade module
#Module Math
#Import Export Math.Vector {*}    ; re-exports Vec2, Vec3
#Import Export Math.Matrix {*}    ; re-exports Mat4

; app.ahk
#Import Math {Vec2, Vec3, Mat4}   ; all resolved through the facade
```

The selective import form (`{Name1, Name2}`) and the star-import form (`{*}` on the
import side) are unchanged; this only adds the `Export ... {*}` direction.

### `GetOwnPropDesc` returns type classes for numeric struct fields

`GetOwnPropDesc` previously returned type codes as strings (e.g. `"i32"`, `"f64"`) for
numerically-typed struct properties. It now returns the **actual type class object**
(`Int32`, `Float64`, etc.), which can be compared by identity, inspected for its name,
or passed directly to other typed APIs.

```autohotkey
Struct Sensor {
    value: Float32
    id:    UInt16
    flags: UInt8
}

desc := Sensor.Prototype.GetOwnPropDesc("value")
MsgBox(desc.Type == Float32 ? "Float32 confirmed" : "unexpected type")

for field in ["value", "id", "flags"] {
    d := Sensor.Prototype.GetOwnPropDesc(field)
    FileAppend(field . " -> " . d.Type.Prototype.__Class . "`n", "*")
}
```

### `a.Ptr` now subclasses `a.base.Ptr` instead of `Struct.Ptr`

Previously every struct's `.Ptr` class was a direct subclass of `Struct.Ptr`,
collapsing the inheritance chain for pointer types. Now `a.Ptr` subclasses
`a.base.Ptr`, preserving the full hierarchy. This means pointer-typed parameters and
`instanceof` checks correctly reflect struct inheritance.

```autohotkey
Struct Shape {
    area: Float64
}

Struct Circle extends Shape {
    radius: Float64
}

; Ptr chain is now: Circle.Ptr -> Shape.Ptr -> Struct.Ptr
MsgBox(Circle.Ptr.base == Shape.Ptr ? "chain intact" : "broken")

; A function accepting Shape.Ptr will also accept Circle.Ptr
; through normal prototype-chain lookup — no manual cast needed.
```

`StructClass[N].Ptr` (pointer type for struct arrays) was also fixed as part of this
change.

## Bug fixes

- **Circular references in `Struct.Ptr` / `Struct[N]` classes** (`c7844d52`) — internal
  circular references prevented the garbage collector from deleting `.Ptr` and array
  classes once the parent struct class went out of scope. Fixed; these classes are now
  collected correctly.

- **Repeat references to struct array classes** (`58fbbdc4`) — multiple references to
  the same struct array class (e.g. `Tile[6]` referenced more than once) caused
  undefined behaviour. Resolved.

- **Nested struct releasing outer struct** (`10c6f306`) — when a nested struct held the
  last reference to its outer struct and was released, undefined behaviour occurred
  during teardown. Now safe.

- **`DllCall` with empty Struct class** (`ca6f77b7`) — passing an uninitialised /
  empty Struct class to `DllCall` triggered undefined behaviour. Now handled correctly.

- **`#Import ":N"` resolving to wrong file under `#Module` in `#Include`** (`51f9739c`)
  — numeric `#Import` references incorrectly resolved when the directive appeared inside
  a module that was itself included via `#Include`. Fixed.

- **`f32` / `f64` type aliases** (`4fe27c30`) — broken by the `GetOwnPropDesc` type-
  class change (`002df24c`). Corrected.

## Internal / build / parser changes

- **`ACT_EXIT` renamed to `ACT_END_MODULE`** (`73dbad7d`) — internal parser action
  constant renamed to better reflect its semantics (marks the end of a module unit
  rather than a process exit). No user-visible behaviour change.
