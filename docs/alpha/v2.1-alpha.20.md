# AutoHotkey v2.1-alpha.20

**Released:** 2026-03-01
**Previous:** [v2.1-alpha.19](./v2.1-alpha.19.md)
**Next:** [v2.1-alpha.21](./v2.1-alpha.21.md)
**Upstream tag:** [`v2.1-alpha.20`](https://github.com/AutoHotkey/AutoHotkey/tree/v2.1-alpha.20)

## Overview

This is a large release dominated by module system work: the `Import` statement and `#Module` directive receive their most significant round of refinements yet, including the addition of the `#Import` directive form, backward-compatible variable export syntax, module reopening, improved search-path resolution, and module object access to any global variable. Alongside that, a new `~!=` regex-not-equal operator is added, error dialogs switch to a more capable rich-text control, and a broad sweep of bug fixes covers hotkeys, `For` loops, static closures, `StrPut`/`StrGet`, GUI functions, and more.

## New features

### `~!=` — regex not-equal operator

The new `~!=` operator is shorthand for `!(a ~= b)`: it performs a regular expression match and returns `true` when the pattern does **not** match the subject string.

```autohotkey
haystack := "hello world"

if haystack ~!= "^\d"          ; true — string does not start with a digit
    MsgBox("No leading digit")

; Equivalent long form:
if !( haystack ~= "^\d" )
    MsgBox("No leading digit")

; Works in assignments too:
isNotEmail := (addr ~!= "@")
```

The precedence and associativity mirror those of `~=`.

---

### `#Import` directive

A new preprocessor directive form of Import is available in addition to the statement form. Where the statement form (`Import {} from "file"`) must appear in executable code, the directive can appear at the top level of a file just like `#Include`:

```autohotkey
#Import MyModule
#Import "lib\utils.ahk"
#Import * from MathLib
#Import {Sin, Cos} from Trig as T
```

The directive form accepts the same syntactic variants as the statement form (bare module name, quoted file path, `{name list} from`, `* from`, and `as alias`). Because it is a directive it is processed before any executable lines, and it supports line continuation naturally.

---

### Module reopening with `#Module`

`#Module` can now reopen a module that was already defined earlier in the same script. Previously, using a `#Module` name that already existed was a duplicate-declaration error. Now the engine switches back to the named module's context, letting its definition span multiple non-contiguous sections of source text.

```autohotkey
#Module Geo

class Point {
    __New(x, y) {
        this.x := x
        this.y := y
    }
}

; ... other modules can appear here ...

#Module Geo   ; reopen — adds more exports to the same module
export global DefaultPoint := Point(0, 0)
```

---

### Module object exposes all global variables

The object returned when a module is imported (e.g. `MyMod := Import("Lib")`) no longer restricts property access to variables that were explicitly exported. Any global variable defined inside the module can now be read or written through the module object. Variables still need to be exported to be imported by name into the caller's namespace, but the module object itself acts as a general-purpose namespace view.

```autohotkey
; math.ahk
#Module Math
global Pi    := 3.14159265358979
global E     := 2.71828182845905
export global Tau := Pi * 2

; main.ahk
#Import Math
MsgBox(Math.Pi)   ; works — Pi is a global, even though not exported
MsgBox(Math.Tau)  ; works — Tau is exported and a global
MsgBox(Tau)       ; works — Tau is imported into the local namespace
```

---

### Variable export uses `export global` syntax

To preserve backward-compatibility with scripts that call a user-defined function named `Export`, exporting a variable now requires the keyword sequence `export global` rather than just `export`:

```autohotkey
#Module Config

export global MaxRetries := 5      ; correct: exports the variable
export global Timeout    := 30000

; These are NOT exports — they are ordinary function calls:
; Export(someValue)         <- calls the Export() function
; export SomeFunc           <- invalid in a module context (use "export global" for vars)
```

Function exports (`export MyFunc(...) {}`) and class exports (`export class Foo {}`) are not affected by this change.

## Changes

### Import checks the local directory first

When resolving a bare module name or relative file path, `Import` and `#Import` now search the directory of the importing file before scanning the configured module search path. This mirrors the behavior of `#Include` and makes co-located libraries resolve without requiring an explicit path.

```autohotkey
; project/
;   main.ahk
;   helpers.ahk   <- found first, before the search path

; main.ahk
#Import helpers   ; resolves to project\helpers.ahk
```

Previously, only the search path was consulted (after the module name had been looked up in the already-loaded module table).

---

### `Import x {}` binds the module name as a global

When importing with a `{}` name list and a bare module name (not a quoted file path), the module name itself is now also introduced into the global namespace even if `as alias` is not specified. Previously only the names inside `{}` were imported.

```autohotkey
#Import {Pi, E} from Math   ; imports Pi, E, and also creates Math in global scope
MsgBox(Pi)                  ; works
MsgBox(Math.Tau)            ; works — Math is available as a module object
```

---

### `Export Import X` allowed without `{}` or `as`

Inside a module, re-exporting an entire imported module no longer requires wrapping the name in `{}` or adding `as`:

```autohotkey
#Module Utils

Export Import Strings   ; re-exports the Strings module as-is
Export Import Math      ; callers who import Utils also get Math
```

Previously, `Export Import X` without `{}` or `as` was rejected; you had to write `Export Import {Fn1, Fn2} from X` or `Export Import X as X`.

---

### `#Module` quoted parameter is now stripped of quotes

If a `#Module` directive is written with a quoted name (e.g. `#Module "MyLib"`), the quote marks are now correctly stripped, so the module is registered as `MyLib`. Previously the quotes were included in the name, which prevented the module from being found by its intended name.

---

### Global/static objects released on exit (restored)

The release of object references held in global and static variables at script exit was temporarily disabled in an earlier alpha. This release restores that behavior and updates it to iterate through all module variable lists, so `__Delete` metamethods are invoked correctly for objects in any module — not only the main module.

---

### Error dialogs use msftedit.dll

The rich-text control in error and warning dialog boxes has switched from `riched20.dll` (RichEdit 2.0) to `msftedit.dll` (RICHEDIT50W). This resolves two classes of issues:

- **UIAutomation hang**: Inspecting the error dialog with an accessibility tool caused the dialog to stop responding.
- **Character rendering**: Emoji, Chinese, Arabic, and other non-Latin characters were displayed with broken glyphs or inconsistent fonts.

---

## Bug fixes

### Hotkey and keyboard handling

- **Key-up hotkey passthrough**: A key-up hotkey no longer passes the key through when the modifiers at release time do not match those at press time. For example, `^RButton up::` being present no longer caused the right mouse button release to pass through after `RButton::` had already consumed the press.
- **Unpaired key-up suppression**: An unpaired key-up hotkey (e.g. `1 Up::`) now correctly suppresses the key when it is also used as a hotkey prefix, provided the `~` flag is not present and the hotkey is not disabled.
- **Prefix hotkey interaction**: `1::` no longer fires after `1 & LButton up::` has been used (and similar combinations involving a key used both as a standalone hotkey and as a prefix in a key-up hotkey).
- **L/R modifier with tilde prefix**: `~RAlt & <::` no longer causes `RAlt::` to fire on the RAlt key-release despite the `~` modifier. The same fix applies to other left/right modifier key combinations.
- **Remap nonexistent key**: A remap whose source key does not exist on the keyboard (`a::b` where `a` is unavailable) no longer causes the script to exit silently.
- **`A_MaxHotkeysPerInterval` / `A_HotkeyInterval`**: Reading these built-in variables in a case-sensitive manner (e.g. `A_maxHotkeysPerInterval`) now returns the correct value. A case-insensitive character comparison is used in the lookup.

### `For` loops and enumerators

- **Implicit empty-string return**: A custom enumerator that falls off the end of its function body (implicitly returning `""`) is no longer treated as returning `true`, which would previously cause an infinite loop. The engine now distinguishes an implicit empty-string return (marker length -1) from a real empty string.
- **Leading space syntax**: `For( a in b )` with a leading space before the opening parenthesis no longer raises a spurious syntax error.

### Static functions and closures

- **Grandparent variable capture**: A static nested function incorrectly stopped variable resolution at the immediate outer function rather than continuing up the chain. Variables of grandparent (and higher) functions are now found correctly when the intermediate function is static.

### `StrPut` / `StrGet`

- **32-bit integer overflow on x64**: String length values were being truncated to 32-bit integers internally, causing incorrect behavior with long strings on 64-bit builds. Internal length tracking is now done with 64-bit types, and the API limit check is applied more consistently during encoding conversions.
- **StrGet crash with address but no length**: A regression introduced in the StrPut/StrGet integer-limit fix caused `StrGet` to crash when called with a raw address and no explicit length. Fixed by using the correct type in the size capping expression.

### GUI

- **`GuiFromHwnd` crash**: Passing a window handle that belongs to a different AutoHotkey script (same process class but different process) caused a crash. The function now verifies that the window belongs to the current process before dereferencing the associated Gui object.
- **`ListView.Add` with Col1 omitted**: Calling `LV.Add(Options)` without the first column value crashed instead of producing an empty first cell.
- **`FileSelect` filter duplication**: When a filter string that lacked `*.` was passed to `FileSelect`, the pattern was duplicated in the dialog's filter display. Fixed.
- **Top submenu click ignored**: The topmost item of a submenu owned by a `Gui` window ignored certain click events. Fixed.

### Parsing and load-time errors

- **Erroneous `Else` placement**: An `Else` (or `Finally`/`Catch`) placed with no preceding `If`/`Try` block previously caused a crash during script load. The parser now raises a proper error.
- **Block comment with semicolon**: A semicolon inside a block comment (`/* ; */`) was prematurely terminating the block comment. The block comment parser now ignores semicolons.
- **`#Include <A_B>` crash**: Using `#Include <A_B>` where neither `A_B.ahk` nor `A.ahk` exist in the library path caused a crash instead of a clean error.
- **`#Import` line continuation**: Line continuation in `#Import` directives (e.g. splitting a long name list across lines) was not handled. Fixed.

### Reflection / metadata

- **`IsOptional` and `IsByRef` for built-in methods**: These property queries on built-in method objects returned wrong results because the implicit `this` parameter was not excluded from the parameter index calculation.
- **`RegWrite` parameter 1**: The first parameter of `RegWrite` was incorrectly declared optional in its metadata, causing incorrect behavior when called without it.

### Debugging

- **String return value corruption**: When a script function returns a string and the debugger is attached, the returned string value was sometimes corrupted. Fixed.

### `CallbackCreate`

- **`ParamCount` validation**: `CallbackCreate` now validates the `ParamCount` argument. A value less than 0 or greater than 255 now returns an error immediately rather than producing undefined behavior.

### `Run` — process handle leak

- **Handle not closed**: `Run` was opening a process handle internally to retrieve the process ID but was not closing it when no `&PID` output variable was provided. The handle is now always closed after the PID is read.

### Object finalization

- **`__Delete` errors inside `Try`**: Errors raised inside a `__Delete` metamethod were silently swallowed if the method was invoked while a `Try/Catch` was active on the same thread. The engine now temporarily clears `EXCPTMODE_CATCH` for the duration of `__Delete` so that errors are always reported (while still using `EXCPTMODE_DELETE` to produce an accurate message).

### `StructFromPtr`

- **Nested struct assignment with `__value`**: Assigning to a nested struct field of a `StructFromPtr` instance when the nested type defines `__value` now works correctly instead of failing.
- **Crash on nested struct assign**: A crash occurred when attempting to assign to a nested struct field of a `StructFromPtr` instance (nested structs are not implemented, so an appropriate error is now raised instead of crashing).

## Internal / build / parser changes

- Fixed two x86 (32-bit) build warnings introduced by the StrPut/StrGet integer-type change.
- Module search path initialization now sets `mCurrFileIndex` and `mCombinedLineNumber` to 0 before dereferencing `A_LineFile`, ensuring consistent results since the search path is resolved only once per program lifetime.
- Each directory in the module search path is now visited at most once per `Import` resolution call, preventing repeated filesystem probing of the same path when it appears multiple times in the path list.
- Minor source file updates (link corrections in `file.cpp`, `util.cpp`, `script_gui.cpp`) and a character-check fix in `Debugger.cpp`.
