# AutoHotkey v2.1-alpha.29

**Released:** 2026-05-10
**Previous:** [v2.1-alpha.28](./v2.1-alpha.28.md)
**Next:** [v2.1-alpha.30](./v2.1-alpha.30.md)
**Upstream tag:** [`v2.1-alpha.29`](https://github.com/AutoHotkey/AutoHotkey/tree/v2.1-alpha.29)

## Overview

Alpha.29 is a focused unset-semantics release. It sharpens how v2.1 mode
communicates "no value" at three levels: function return conventions, operator
short-circuiting through the maybe (`?`) operator, and a broad pass over
built-in functions. The net effect is that missing values surface as `unset`
rather than silent empty strings — making bugs visible that previously went
undetected.

The release also fixes two Struct/class prototype edge cases introduced
in earlier alpha builds.

---

## New features

### Maybe operator (`?`) short-circuits most operators

The `?` suffix on a variable promotes it to the `unset` sentinel instead of
throwing. In alpha.29 that sentinel propagates through most binary operators
(`||`, `&&`, comparisons, arithmetic, bitwise, ternary, etc.) rather than
raising an error inside the operator. The whole subexpression becomes `unset`,
which you handle at the call site with `??` or `IsSet()`.

```ahk
; unsetVar is never assigned — ? makes it a safe sentinel
result := unsetVar? > 0   ; does not throw inside >; result is unset

; Use ?? to supply a fallback at the boundary you control
safe := (unsetVar? + 10) ?? 0
MsgBox(safe)   ; 0
```

Previously this short-circuit worked only for a narrow set of operators;
now it covers most expression operators, making the feature practically usable.

### Fat-arrow tail calls propagate blank-unset return (`a() => b()`)

A fat-arrow function that tail-calls another function or method now transparently
propagates a blank-unset return. Previously, if `b()` returned without a value,
`a()` would produce an empty string instead of no value.

```ahk
VoidFn() {
    return          ; no expression — blank-unset
}

Wrapper() => VoidFn()   ; now also blank-unset, not ""

got_value := true
try
    x := Wrapper()
catch
    got_value := false

MsgBox(got_value ? "value returned" : "no value — propagated correctly")
```

Restrictions:
- Applies to tail calls of **functions and methods** only, not property accesses.
- Does **not** apply to explicit `return unset` or `return (x?)` — those are
  intentional and remain unchanged.

### v2.1 mode: default return is `unset` when any `return expr` is present

In v2.1 mode, if a function body contains at least one `return <expression>`,
any code path that falls through without hitting a return statement now implicitly
returns `unset` instead of a blank-unset value. This catches the common mistake of
forgetting a return branch.

```ahk
#Requires AutoHotkey v2.1-alpha.29

EvenOrUnset(n) {
    if Mod(n, 2) = 0
        return n
    ; no explicit return for odd — falls through as unset
}

FileAppend(EvenOrUnset(4) ?? "<unset>" . "`n", "*")   ; 4
FileAppend(EvenOrUnset(5) ?? "<unset>" . "`n", "*")   ; <unset>
```

In functions that have **no** `return expr` at all (only bare `return` or
fall-through), the behaviour is unchanged — those remain blank-unset.

## Changes

### Built-in functions return `unset` for missing/no-match in v2.1 mode

A broad set of built-in functions and properties now return `unset` (rather
than an empty string or `0`) when the requested item does not exist or the
operation has nothing meaningful to return. This only affects scripts running
in v2.1 mode.

**Array methods:**

| Method | Condition that now returns `unset` |
|---|---|
| `Array.Delete(i)` | The slot at index `i` had no value (was a hole) |
| `Array.Pop()` | The array had no last element, or last element was a hole |
| `Array.RemoveAt(i)` | The slot removed was a hole |

```ahk
arr := [1, , 3]          ; element 2 is a hole
removed := arr.RemoveAt(2) ?? "<unset>"
MsgBox(removed)          ; <unset>

arr2 := [10, 20, 30]
popped := arr2.Pop() ?? "<unset>"
MsgBox(popped)           ; 30  (value present — still works normally)
```

**Object reflection methods:**

| Method | Condition that now returns `unset` |
|---|---|
| `Object.DeleteProp(name)` | Property did not exist |
| `Object.GetMethod(name)` | Method not found |
| `Object.GetOwnPropDesc(name)` | Property not defined on this object |

```ahk
obj := {a: 1}
gone := obj.DeleteProp("nope") ?? "<unset>"     ; <unset>
m    := obj.GetMethod("missing") ?? "<unset>"   ; <unset>
desc := obj.GetOwnPropDesc("b") ?? "<unset>"    ; <unset>
```

**GUI functions and properties:**

| Symbol | Condition |
|---|---|
| `Gui.MenuBar` | No menu bar assigned |
| `Gui.FocusedCtrl` | No control has focus |
| `Gui[name]` | Control not found |
| `GuiFromHwnd(hwnd)` | HWND is not a Gui |
| `GuiCtrlFromHwnd(hwnd)` | HWND is not a Gui control |
| `MenuFromHandle(handle)` | Handle does not map to a Menu |

```ahk
g_lookup  := GuiFromHwnd(0)     ?? "<unset>"   ; <unset>
gc_lookup := GuiCtrlFromHwnd(0) ?? "<unset>"   ; <unset>
mn_lookup := MenuFromHandle(0)  ?? "<unset>"   ; <unset>
```

**Other built-ins:**

- `InputHook.OnEnd`, `InputHook.OnChar`, `InputHook.OnKeyDown`,
  `InputHook.OnKeyUp` — getting an unassigned handler now returns `unset`.
- `ObjGetBase(obj)` / `Any.Prototype.Base` — returns `unset` when `obj` is at
  the top of the prototype chain (no base). Previously returned `""`, making
  chain-walking loops awkward.
- `RegExMatch` output variable — left unset on no-match. `IsSet(outputVar)` now
  cleanly distinguishes match from miss.

```ahk
; Walk a prototype chain to its top
p := MyClass.Prototype
loop {
    next := ObjGetBase(p) ?? unset
    if !IsSet(next)
        break
    p := next
}

; Distinguish regex match vs no-match
RegExMatch("hello", "x",  &m1)   ; no match
RegExMatch("hello", "l+", &m2)   ; match
MsgBox(IsSet(m1) ? "matched" : "no match")   ; no match
MsgBox(IsSet(m2) ? m2[0] : "no match")       ; ll
```

## Bug fixes

- Fixed `(()=> a? || 1)()` crashing the parser. An IIFE containing a fat-arrow
  that applied the maybe operator inside a binary expression caused a parse error;
  now evaluates cleanly. (`source/script.cpp`, `source/util.cpp`)
- Fixed `Map` and `Array` not throwing `UnsetItemError` in v2.0 mode when an
  access with an unset result went unused. These now throw as expected.

---

## Internal / build / parser changes

- `source/defines.h`: new flag to track whether a function has any `return expr`
  (used by the v2.1 default-return change); operator short-circuit table expanded.
- `source/script.cpp` / `source/script.h`: parser updated for tail-call
  propagation, default-return detection, and extended `?` short-circuit table
  (~275-line net change to `script.cpp` in the `?` commit alone).
- `source/script_expression.cpp`: expression evaluator handles `unset` sentinel
  pass-through for the expanded operator set.
- `source/script_object.cpp`: `Struct.Array.Prototype` sealed against new typed
  properties; `ClassObj.Prototype.Base` made writable when the class has no typed
  properties.
- `source/script_object_bif.cpp`, `source/script_gui.cpp`,
  `source/input_object.cpp`: return-type annotations changed to `unset`-capable
  for the affected built-ins.
