# AutoHotkey v2.1-alpha.26

**Released:** 2026-04-12
**Previous:** [v2.1-alpha.25](./v2.1-alpha.25.md)
**Next:** [v2.1-alpha.27](./v2.1-alpha.27.md)
**Upstream tag:** [`v2.1-alpha.26`](https://github.com/AutoHotkey/AutoHotkey/tree/v2.1-alpha.26)

## Overview

Alpha.26 is primarily a stability, correctness, and memory-efficiency release. The headline
changes are a rewrite of the internal message-dispatch loop (fixing keyboard shortcuts in modal
dialogs and Tab navigation in nested GUIs), a switch to `WM_CLOSE` for `#SingleInstance`/`Reload`
shutdown, several struct-system fixes (array alignment, `StructClass.Ptr` sealing, typed-callback
return types), a new `DllCall` convenience for struct output parameters, and a significant
reduction in per-object heap allocations by co-locating typed-property data with the owning object.

Of the 33 commits in this range, approximately 20 are internal refactors, dead-code removal, and
build-system cleanups that carry no user-facing effect. The user-visible changes are documented
below; purely internal or build-only commits are summarised in the final section.

## New features

### `DllCall(F, StructType, unset)` auto-creates a default instance

When `unset` is passed as the value for a struct-typed parameter in a `DllCall` or `ComCall`
expression, and the struct type has no `__Value` setter, AHK now automatically allocates a default
instance (`S()`) in its place. This is the natural pattern for output-only parameters where the
called function writes into a caller-supplied struct.

**Before alpha.26** you had to pre-allocate manually even when there was nothing useful to put in
the struct yet:

```ahk
st := SYSTEMTIME()                              ; forced pre-allocation
DllCall("GetLocalTime", "Ptr", st.Ptr)          ; pass raw pointer
```

**After alpha.26** you can let `DllCall` do the allocation:

```ahk
Struct SYSTEMTIME {
    wYear:         u16
    wMonth:        u16
    wDayOfWeek:    u16
    wDay:          u16
    wHour:         u16
    wMinute:       u16
    wSecond:       u16
    wMilliseconds: u16
}

; Pass the struct type as the type specifier and `unset` as the value.
; DllCall creates SYSTEMTIME() automatically because the type has no __Value setter.
DllCall("GetLocalTime", SYSTEMTIME, st := SYSTEMTIME())
MsgBox(Format("{}-{:02}-{:02} {:02}:{:02}:{:02}",
    st.wYear, st.wMonth, st.wDay,
    st.wHour, st.wMinute, st.wSecond))
```

The `S()` instance is created before the native call and, after the call returns, the caller can
read the populated fields from `st`. The behaviour is unchanged when the type supplies a `__Value`
setter (the setter is called with `unset` as before).

## Changes

### `#SingleInstance` and `Reload` now post `WM_CLOSE` to the old instance

Previously, `#SingleInstance` and `Reload` sent an internal AHK message to terminate the running
instance. The old instance now receives a standard `WM_CLOSE` message instead.

**Practical effect:** `OnExit` callbacks registered in the outgoing script fire under the normal
`Close` reason, so all existing cleanup code works as expected without any changes.

```ahk
#SingleInstance Force

OnExit(CleanUp)
CleanUp(reason, code) {
    ; reason is "Close" when a new instance of this script starts
    FileAppend(A_Now " | " reason "`n", "exit_log.txt")
}

; When a second instance of this script is launched, the running
; instance receives WM_CLOSE, CleanUp fires, then the new instance takes over.
```

### Message handling rewritten to fix modal-dialog limitations

The internal Windows message pump (`MsgSleep` / dialog loops) was substantially refactored
(`application.cpp`, 412 lines touched). Two visible regressions in earlier alpha builds are
resolved:

1. **Keyboard shortcuts while a modal dialog is open.** Hotkeys assigned to `Ctrl`+key, `Alt`+key,
   and other accelerators that belong to background GUI windows were silently dropped while a
   `MsgBox`, `InputBox`, or other modal dialog was displayed. They now fire correctly.

2. **Tab-key navigation in a `Gui` containing a nested `Gui` (`+Parent`)** (see dedicated entry
   below).

The internal `POST_AHK_DIALOG` mechanism was also simplified: the helper `WM_COMMNOTIFY` wrapper
is no longer needed, as the dialog message loop dispatches messages without the previous filtering
restriction.

### `POST_AHK_DIALOG` now uses `AHK_DIALOG` directly

An internal follow-on to the message-handling rewrite. The `POST_AHK_DIALOG` macro now posts
`AHK_DIALOG` directly rather than routing it through a `WM_COMMNOTIFY` envelope. No API change;
included for completeness.

## Bug fixes

### IsSet — expressions ending with `?` now accepted

`IsSet()` previously rejected expressions whose argument ended with the maybe-unset operator `?`,
raising a parse error. The parser now correctly handles this form.

```ahk
; Both forms now work in alpha.26:
val := "hello"
MsgBox(IsSet(val))      ; 1
MsgBox(IsSet(nope))     ; 0

; The maybe-unset operator on an unset variable yields "unset" rather than
; throwing; IsSet can now be used with that combined pattern.
CheckMaybe(v?) {
    if IsSet(v)
        MsgBox("got: " v)
    else
        MsgBox("nothing passed")
}
CheckMaybe()        ; "nothing passed"
CheckMaybe("hi")    ; "got: hi"
```

### Struct — array fields now align correctly

Struct array members were not being aligned to their natural boundary when preceded by a smaller
field. For example, a `Float64[3]` following a `u8` field would be placed at offset 1 instead of
the required offset 8. This produced wrong field offsets and incorrect struct sizes.

The alignment logic now respects each element type's natural alignment requirement for array
fields, matching the C ABI for the corresponding struct layout.

```ahk
Struct AlignedRecord {
    id:     u8
    values: Float64[3]  ; must start at an 8-byte boundary
    flags:  u32
}

rec := AlignedRecord()
rec.id       := 42
rec.values[1] := 1.111
rec.values[2] := 2.222
rec.values[3] := 3.333
rec.flags    := 0xFF

; In alpha.25 the size and field reads were wrong due to misalignment.
; In alpha.26 the layout matches the equivalent C struct.
MsgBox(Format("size={} id={} flags=0x{:02X} v1={:.3f}",
    rec.Size, rec.id, rec.flags, rec.values[1]))

; Struct arrays also align correctly:
Struct Vec2 { x: Float64 ; y: Float64 }
points := Vec2[4]()
Loop 4 {
    points[A_Index].x := A_Index * 10.5
    points[A_Index].y := A_Index * 20.5
}
; Expect size = 64 (4 * 16 bytes)
MsgBox(Format("Vec2[4] size={}", points.Size))
```

### Struct — accessing `StructClass.Ptr` no longer seals the struct definition

Evaluating the `.Ptr` property on a struct **class** (not an instance) prematurely marked the
struct as sealed, preventing any subsequent definition changes. This was unintentional; the sealing
should only happen when the struct is first instantiated.

```ahk
Struct Header {
    magic:   u32
    version: u16
}

; In alpha.25 this call sealed Header, causing errors if the struct
; definition was modified afterwards.
ptrType := Header.Ptr   ; safe in alpha.26

; The struct remains fully usable after the property access:
h         := Header()
h.magic   := 0x46465542
h.version := 26
MsgBox(Format("magic=0x{:08X} ver={}", h.magic, h.version))
```

### Struct — typed callback return types now handled correctly

When `CallbackCreate` is used with a typed (struct) return type, the return value was processed
using the wrong code path. The fix ensures the struct value is properly marshalled on return from
the callback.

```ahk
; Typed struct return from a callback — now works correctly.
Struct Point { x: Float32 ; y: Float32 }

MakePoint(xVal, yVal) {
    p := Point()
    p.x := xVal
    p.y := yVal
    return p
}

cb := CallbackCreate(MakePoint, , 2)
; The return value is now a valid Point struct rather than garbage.
CallbackFree(cb)
```

### Callback — `__Value` return-value conversion fixed

When a callback returned an object that defined `__Value`, the conversion was using the wrong
variable binding, which could produce an incorrect value or a crash. The binding is now correct.

```ahk
class Wrapper {
    __Value => this._v
    __New(v) { this._v := v }
}

; A callback returning Wrapper(42) now correctly yields 42 to the caller
; rather than an undefined or zero value.
```

### GUI — Tab key navigation fixed in `Gui` with nested `+Parent` child

A child `Gui` created with the `+Parent` option lacked the `WS_EX_CONTROLPARENT` extended style
(`0x00010000`). Windows requires this style to chain Tab-key focus traversal through nested
windows. Without it, Tab would get stuck at the boundary between parent and child controls.

The style is now applied automatically. No script changes are needed.

```ahk
parentGui := Gui()
parentGui.Add("Edit", "w200", "Field in parent")

childGui := Gui("+Parent" parentGui.Hwnd)
childGui.Add("Edit", "w200", "Field in child")
childGui.Add("Button", "Default w200", "OK")

parentGui.Show()
; Tab now cycles through all controls in both parent and child.
```

### GUI / Start menu — shown menu no longer prevents Start menu from opening at high IL

When a script running as Administrator or with UIAccess had an active context menu visible, clicking
the Windows Start button failed to open the Start menu. The script's menu was capturing foreground
activation and blocking the shell. The fix corrects the window-activation handling so the Start
menu can always be opened regardless of what the script's menus are doing.

No code change required in scripts; this is an internal fix to `application.cpp`.

## Internal / build / parser changes

These commits have no user-facing API changes but are recorded for completeness.

### Memory layout — struct and typed-property data co-allocated with owning object

Two related commits (`Combine Struct data allocation with main Object`, `Combine Object data
allocation with main Object`) merge the heap block for typed property data (previously a separate
allocation) into the single allocation for the containing `Object`. The result is:

- One heap allocation instead of two per struct instance.
- Better cache locality for field access in tight loops.
- Reduced peak RSS for scripts that create large numbers of struct objects.

No API or AHK-language change. Existing scripts automatically benefit.

### `StructInfo` separated from `mData`

`StructInfo` (the compile-time struct metadata) is now stored separately from the per-instance
data buffer (`mData`). This decouples the layout description from live object memory, making the
internal representation cleaner for the construction-path revisions that follow.

### Construction path revised (parts 1 and 2)

`d725597d` / `482284b0` — Two-stage refactor of how struct instances are constructed. No
user-visible change; the revision is groundwork for the co-allocation improvements above.

### `GetStructInfo` revised and usage reviewed

`038afdfd` / `e009ecac` — `GetStructInfo` is refactored to return a cleaner representation.
Internal callers updated to match. No script-level effect.

### `StructClass.Prototype` query bypassed in `DllCall`

`31337e1f` — A redundant `StructClass.Prototype` property lookup on every `DllCall` with a struct
type argument is now skipped, reducing overhead in struct-heavy DllCall paths.

### Unused code removed

Several commits (`a050780b`, `eb00e949`, `1c4bc885`, `3347b025`, `9e839af5`) remove the
`DataIsAllocatedFlag` field, unused helper functions, and a redundant `size` field in object
allocated data. Code-size reduction only.

### `CreateRootPrototypes` and related functions optimised for code size

`674d696b` — Template-based and other minor refactors reduce binary size for prototype
initialisation. No behavioural change.

### `Class_New` calls `NewInstance` directly when `aParamCount == 1`

`92bbd52e` — Minor code-size optimisation in the class-construction dispatch. No observable
change for scripts.

### `BuiltInFunc` ID and data passed directly in `ResultToken`

`003cbcaa` — Internal plumbing: built-in function identity/data is stored directly in the
`ResultToken` rather than being re-fetched. Reduces indirection in the call path. No script-level
effect.

### `IObjectRef` added to manage `DllCall` parameter type objects

`7e29ec42` — A new `IObjectRef` RAII wrapper is used to manage the lifetime of parameter-type
objects inside `DllCall`. This fixes an incorrect `Release` call that could manifest as a
use-after-free in certain struct-typed `DllCall` patterns.

### `CreateCArrayClass` minor optimisation

`0735b945` — Small tweak to the C-array class factory. No observable change.

### Template replaces `_countof` for `ClassDef` member lists

`e1acf163` — A C++ template is used instead of the `_countof` macro for class definition member
arrays. Build/toolchain change only.

### Typo fixes in `window.cpp` comments

`0769374a` — Comment-only change; no code altered.
