# AutoHotkey v2.1-alpha.28

**Released:** 2026-04-26
**Previous:** [v2.1-alpha.27](./v2.1-alpha.27.md)
**Next:** [v2.1-alpha.29](./v2.1-alpha.29.md)
**Upstream tag:** [`v2.1-alpha.28`](https://github.com/AutoHotkey/AutoHotkey/tree/v2.1-alpha.28)

## Overview

This release finalises the v2.0 / v2.1 mode-switching mechanism. `#DefaultReturn` is
removed; `#Requires` now automatically sets backward-compatibility mode based on the
version it specifies. Built-in functions that returned an empty string when they had no
meaningful value to return now return `unset` instead when running in v2.1 mode. Several
struct-related bugs are fixed, and two correctness bugs around `ByRef` aliases and
`OnMessage` callbacks are resolved.

---

## Changes

### `#Requires` now sets the v2.1 compatibility mode automatically

`#Requires AutoHotkey v2.1-alpha.X` (or any version that would not be satisfied by v2.0)
now enables v2.1 mode for the file that contains the directive. `#Requires
AutoHotkey v2.0` (or a range that v2.0 still satisfies) keeps v2.0-compatible mode.

The mode is scoped to the file. When the file ends, the calling file's mode is restored.
This means `#include`-ing a file that requires v2.1 does not force v2.1 mode on the
caller.

The mode is stored per-function at parse time, so a function defined after a v2.1
`#Requires` line behaves differently from a function defined before it in the same file.

```autohotkey
#Requires AutoHotkey v2.1-alpha.28
; v2.1 mode: bare `return` inside a function returns unset, not ""
MyFunc() {
    return  ; equivalent to `return unset` in v2.1 mode
}
val := MyFunc()
MsgBox(IsSet(val) ? "set" : "unset")  ; -> "unset"
```

```autohotkey
#Requires AutoHotkey v2.0
; v2.0 mode: bare `return` still returns ""
MyFunc() {
    return
}
MsgBox(MyFunc() == "" ? "empty string" : "other")  ; -> "empty string"
```

### `#DefaultReturn` directive removed

The `#DefaultReturn unset` / `#DefaultReturn ""` directive introduced in an earlier alpha
is removed. Use `#Requires AutoHotkey v2.1-...` to opt into v2.1 semantics, which
implicitly sets the default return to `unset`.

> **Breaking change:** Any script using `#DefaultReturn` must switch to
> `#Requires AutoHotkey v2.1-alpha.X` to keep v2.1 return semantics.

### Built-in functions return `unset` instead of `""` in v2.1 mode

In v2.0, built-in functions that had no meaningful return value returned an empty string.
In v2.1 mode, those same functions now return `unset` (i.e. `SYM_MISSING`). This aligns
them with the v2.1 convention that "no value" and "empty string" are distinct.

Affected functions include the various `Hotkey`, file I/O, window, GUI, and other
side-effecting BIFs that previously returned `""` unconditionally.

```autohotkey
#Requires AutoHotkey v2.1-alpha.28
FileAppend("hello`n", "test.txt")
result := FileAppend("hello`n", "test.txt")
MsgBox(IsSet(result) ? "set" : "unset")  ; -> "unset" in v2.1 mode
```

### `Map` and `Array` now raise `UnsetItemError` instead of `UnsetError`

When a `Map` or `Array` item exists but its value is unset (e.g. set to `unset`
explicitly), accessing it now raises `UnsetItemError` rather than the more generic
`UnsetError`. This matches the intended distinction in v2.1's error hierarchy.

```autohotkey
#Requires AutoHotkey v2.1-alpha.28
m := Map()
m["x"] := unset
try
    val := m["x"]
catch UnsetItemError as e
    MsgBox("Caught UnsetItemError: " . e.Message)
```

## Struct changes

### `StructClass.Prototype` is now read-only

`StructClass.Prototype` can no longer be reassigned. Struct classes store a direct
pointer to their prototype and bypass the normal property-bag lookup for it, so allowing
assignment was misleading and inconsistent. This change also enables an internal
optimisation that reduces code size.

```autohotkey
#Requires AutoHotkey v2.1-alpha.28
Struct Point { x: i32, y: i32 }
try
    Point.Prototype := Object()  ; throws — Prototype is read-only for struct classes
catch Error as e
    MsgBox(e.Message)
```

### `StructClass.At()` now accepts struct classes with no fields

Previously, `StructClass.At(ptr)` threw `"Invalid class"` if the struct had no fields.
It now succeeds for zero-field structs, which is useful when working with opaque handle
types or when using the pointer purely for its address.

```autohotkey
#Requires AutoHotkey v2.1-alpha.28
Struct Handle { }  ; opaque handle — no declared fields
; StructClass.At(ptr) no longer throws for zero-field structs
ptr := 0x12340000
; h := Handle.At(ptr)  ; valid in alpha.28+
MsgBox("StructClass.At() accepts zero-field structs")
```

## Bug fixes

- **`return unset` from an `OnMessage` callback now acts as `return ""`.**
  `OnMessage` callbacks use the return value to determine whether to pass the message
  on; returning unset must behave the same as returning an empty string (pass through),
  not propagate as an error. The internal `TokenIsEmptyString` helper was renamed to
  `TokenIsBlank` and updated so that `SYM_MISSING` tokens are treated as blank in
  the contexts where the old function was called.

- **Error raised by `Hotkey()` now transfers control correctly.**
  When `Hotkey()` failed to add a new hotkey, it returned `FAIL` instead of `FR_FAIL`.
  The distinction matters for how the result propagates through the calling convention;
  using `FAIL` could leave the script in an unexpected control-flow state.

- **`ByRef` alias to a global variable no longer becomes unset in recursive calls.**
  When a function was called recursively and one of its parameters was a `ByRef` alias
  pointing to a global variable, the alias could be incorrectly resolved or backed up
  as if it were a local variable, causing the variable's value to appear unset on return.

  ```autohotkey
  #Requires AutoHotkey v2.1-alpha.28
  global counter := 0

  Increment(&val) {
      val += 1
      if (val < 3)
          Increment(&val)  ; recursive — val must still refer to the same global
  }

  Increment(&counter)
  MsgBox("counter = " . counter)  ; should be 3
  ```

- **Fixed classes with inherited nested structs.**
  A struct class that inherited from another struct class which itself contained nested
  struct fields would fail to copy the nested struct information into the derived class,
  leading to incorrect layout or a crash when instantiating the derived type.

- **Fixed `StructClass.At()` where the struct class has a nested struct.**
  `StructClass.At(ptr)` would operate incorrectly when the struct class contained a
  nested struct sub-field. This was broken by commit `6979d3ad` in alpha.27.

- **Fixed `ObjSetDataPtr()` throwing on success.**
  The function was missing a `return OK;` after successfully setting the data pointer,
  causing it to fall through to `return FR_E_FAILED` even when the operation succeeded.

## Internal / build changes

- **`Var::GetRef()` no longer performs unnecessary `AddRef`/`Release` calls.**
  When returning an existing `VarRef` object for a variable that already holds one, the
  previous code incremented and then immediately decremented the reference count. The
  extra pair of calls is removed. A related `Release()` after calling `GetRef()` in
  `UserFunc::Call()` is also removed.

- **`ExprTokenType` gains an `UnsetKind` discriminator.**
  A new `UnsetKind` enum (`Blank`, `Unset`, `UnsetItem`, `Unspecified`) is stored inside
  `SYM_MISSING` tokens. This lets the expression evaluator propagate the correct error
  type (e.g. `UnsetItemError` vs `UnsetError`) when an unset value is accessed
  unexpectedly, and lets v2.0-mode built-ins return a token that resolves to `""` rather
  than truly `unset`.

- **`ResultToken::InitResult()` now initialises to `SYM_MISSING` with `UnsetKind::Blank`**
  rather than to an empty string. This is what enables built-ins to return `unset` by
  default in v2.1 mode — the runtime converts `UnsetKind::Blank` tokens back to `""`
  when in v2.0 mode.

- **`TokenIsEmptyString()` renamed to `TokenIsBlank()`.**
  The internal helper is renamed to reflect that it now covers `SYM_MISSING` tokens with
  `UnsetKind::Blank` as well as empty strings, matching the new semantics.
