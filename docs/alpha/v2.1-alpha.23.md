# AutoHotkey v2.1-alpha.23

**Released:** 2026-03-22
**Previous:** [v2.1-alpha.22](./v2.1-alpha.22.md)
**Next:** [v2.1-alpha.24](./v2.1-alpha.24.md)
**Upstream tag:** [`v2.1-alpha.23`](https://github.com/AutoHotkey/AutoHotkey/tree/v2.1-alpha.23)

## Overview

This release delivers two closely related Struct additions: built-in numeric type classes
(`Int8`, `UInt16`, `Float32`, etc.) and structured array classes (`StructClass[N]`). Together
they make it possible to define typed, contiguous arrays and Win32-compatible structs with
precise field widths, all without `Buffer` / `NumPut` / `NumGet` boilerplate. Several hotkey
suppression edge cases are also fixed, along with parser bugs in continuation sections, and
a handful of `#Import` / `#Module` reliability improvements.

---

## New features

### Built-in numeric Struct classes

Alpha.23 ships a set of predefined classes that each extend `Struct` with a single numeric
field. They are named after the C types they correspond to and are always available — no
`#Include` is needed.

| Class | Backing type | Bytes |
|-------|-------------|-------|
| `Int8` | signed 8-bit integer | 1 |
| `UInt8` | unsigned 8-bit integer | 1 |
| `Int16` | signed 16-bit integer | 2 |
| `UInt16` | unsigned 16-bit integer | 2 |
| `Int32` | signed 32-bit integer | 4 |
| `UInt32` | unsigned 32-bit integer | 4 |
| `Int64` | signed 64-bit integer | 8 |
| `UInt64` | unsigned 64-bit integer | 8 |
| `IntPtr` | pointer-sized signed integer | 4 or 8 |
| `UIntPtr` | pointer-sized unsigned integer | 4 or 8 |
| `Float32` | 32-bit IEEE float | 4 |
| `Float64` | 64-bit IEEE float | 8 |

These classes serve two purposes: they can be used as **field types** in a `Struct`
declaration, and they can be subscripted with `[N]` to produce a typed array class (see
next section).

```autohotkey
#Requires AutoHotkey v2.1-alpha.23

; Struct with typed fields — replaces Buffer + NumPut/NumGet patterns
Struct SensorReading {
    timestamp:   Int64
    temperature: Float32
    humidity:    Float32
    sensor_id:   UInt16
    flags:       UInt8
}

reading := SensorReading()
reading.timestamp   := 1711234567890
reading.temperature := 22.5
reading.humidity    := 45.2
reading.sensor_id   := 1042
reading.flags       := 0x03

MsgBox(Format("temp={:.1f}  id={}  flags=0x{:02X}  size={} bytes",
    reading.temperature, reading.sensor_id, reading.flags, reading.Size))
```

`Float32` and `Float64` also work as standalone struct values for scalar GPU / math
interop:

```autohotkey
Struct Vec3f {
    x: Float32
    y: Float32
    z: Float32
}

v := Vec3f()
v.x := 1.5, v.y := 2.7, v.z := -3.14
MsgBox(Format("Vec3f({:.2f}, {:.2f}, {:.2f}) — {} bytes", v.x, v.y, v.z, v.Size))
; Vec3f(1.50, 2.70, -3.14) — 12 bytes
```

### Typed array classes via `StructClass[N]`

Any class that extends `Struct` — including the new numeric classes — now supports subscript
syntax to create a fixed-length, contiguous array class:

```
ArrayClass := StructClass[N]
```

The resulting class has:

- `obj[i]` — 1-based element access (negative indices count from the end, so `obj[-1]` is
  the last element).
- `obj.Length` — element count (`N`).
- `obj.Size` — total byte size (`N × element size`), accounting for struct alignment.
- The underlying memory is a single contiguous allocation, suitable for passing to DllCall
  as a `Ptr`.

```autohotkey
#Requires AutoHotkey v2.1-alpha.23

; Typed integer array
a := Int32[4]()
a[1] := 10, a[2] := 20, a[3] := 30, a[4] := 40

MsgBox(Format("Int32[4]: [{}, {}, {}, {}]  size={} bytes  length={}",
    a[1], a[2], a[3], a[4], a.Size, a.Length))
; Int32[4]: [10, 20, 30, 40]  size=16 bytes  length=4

; Negative indexing — last element
MsgBox(Format("a[-1] = {}", a[-1]))   ; 40

; Float array
f := Float64[3]()
f[1] := 3.14159, f[2] := 2.71828, f[3] := 1.41421
MsgBox(Format("Float64[3]: [{:.5f}, {:.5f}, {:.5f}]  {} bytes",
    f[1], f[2], f[3], f.Size))
; Float64[3]: [3.14159, 2.71828, 1.41421]  24 bytes
```

Struct classes can also be subscripted, producing arrays of structs whose elements share
contiguous memory — useful for bulk DllCall scenarios (e.g., `POINT[N]` for
`GetMouseMovePointsEx`):

```autohotkey
#Requires AutoHotkey v2.1-alpha.23

Struct POINT {
    x: Int32
    y: Int32
}

; Array of 3 POINTs — 24 bytes contiguous
pa := POINT[3]()
pa[1].x := 10,  pa[1].y := 20
pa[2].x := 100, pa[2].y := 200
pa[3].x := 50,  pa[3].y := 150

MsgBox(Format("POINT[3]: {} bytes", pa.Size))   ; 24

out := ""
loop pa.Length
    out .= Format("[{}]=({}, {})  ", A_Index, pa[A_Index].x, pa[A_Index].y)
MsgBox(out)
```

#### Byte buffer pattern

`UInt8[N]` is a clean, typed alternative to `Buffer(N)` for raw byte arrays:

```autohotkey
h := UInt8[32]()
loop 32
    h[A_Index] := Mod(A_Index * 17, 256)

hex := ""
loop 8
    hex .= Format("{:02X} ", h[A_Index])
MsgBox(hex . "...")   ; 11 22 33 44 55 66 77 88 ...
```

## Changes

### `Struct.Prototype.Size` now returns layout size

Prior to this fix, `instance.Size` returned the internally allocated buffer size, which
could differ from the struct's logical layout size due to over-allocation. It now
consistently returns the size of the struct's memory layout — the value you would get from
`sizeof` in C.

```autohotkey
Struct SmallPair {
    a: UInt8
    b: UInt8
}

s := SmallPair()
MsgBox(Format("SmallPair.Size = {}", s.Size))   ; 2, not a larger allocation size
```

This is a correctness fix with no API change; scripts that passed `instance.Size` as a byte
count to DllCall or FileAppend will now receive the accurate value.

### Removed undocumented side-effect of side-specific hotkeys on neutral variants

Using a left- or right-specific prefix hotkey (e.g. `<^a::`) no longer silently alters the
behaviour of the corresponding neutral hotkey (`LCtrl::`). The documentation states that
"a specific left or right hotkey such as `LCtrl::` fires when it is pressed down." That
contract is now enforced without undocumented interference from side-specific forms.

### File write buffers are flushed on exit

AHK now explicitly flushes all open `FileOpen` write buffers at program exit. Previously,
buffered writes to files opened with `FileOpen` could be lost if the script exited before
the OS flushed the buffer. Console output via `FileOpen("*", "w")` and any other buffered
file handles are now reliably written before the process terminates.

## Breaking changes

### Side-specific hotkeys no longer suppress neutral key-up hotkeys unexpectedly

The removal of the undocumented `<^a::` → `LCtrl::` side-effect (see Changes above) may
alter behaviour in scripts that were relying on it, even inadvertently. If `LCtrl::` in
your script was behaving differently depending on whether `<^...` hotkeys were present,
audit those hotkeys after upgrading.

## Bug fixes

### Hotkeys and key suppression

- **`~LCtrl up::`** no longer suppresses `LCtrl` even when a `LCtrl::` hotkey is present.
  The `~` (passthrough) prefix was being ignored in this case. (`b64bf33e`)
- **Neutral `Ctrl`/`Alt`/`Shift` hotkeys** no longer suppress the key. Additionally,
  "fire-on-release" behaviour (triggered when a key-up variant exists but is disabled by
  `#HotIf`) now works correctly for neutral modifier hotkeys. (`15205f79`)
- **`CapsLock & 1::`** now reverts `CapsLock` state correctly even when another prefix key
  is pressed before `CapsLock` is released. (`9e53c7b7`)
- **`CapsLock::`** now suppresses the key even when `CapsLock` is also used as a prefix key
  in another hotkey. (`6f7d352c`)
- **L/R modifier key-up** suppression is now applied consistently in cases where key-down
  was suppressed but key-up was not. (`08d8a31b`)
- **Orphan key-up events** (a key-up with no matching tracked key-down) no longer
  incorrectly trigger a prefix key's key-down hotkey. (`3e71fcc3`)

### Parser / continuation sections

- **Semicolons inside continuation sections** with the `\`` (literal escape) join option are
  now parsed correctly. A `;` that should have been treated as a literal character was
  instead terminating the section prematurely. (`e19c6744`)
- **Unquoted continuation sections with trailing spaces** no longer produce corrupted output.
  Trailing spaces on lines within an unquoted continuation section were causing off-by-one
  data corruption. (`51e21131`)

### `#Import` / `#Module`

- **`#Import "Path:__Init"`** now resolves correctly even when the imported file has no
  `#Module` directive. Previously this form would fail to find the init function when
  `#Module` was absent. (`08332c6d`)
- **Explicitly importing built-in objects** from an AHK module (e.g. `#Import Array`) now
  works as expected. (`631dafc2`)
- **`#Import` self-referential loops** (a variable import alias pointing to itself) are now
  detected and rejected, preventing infinite resolution loops. (`c80a2336`)

### Struct / class validation

- **A class can no longer declare itself as its own base class.** Such a declaration is now
  caught at parse time with an appropriate error. (`236f3201`)
- **Base class validation** in `Struct` and `class` declarations no longer depends on the
  order in which classes appear in source. Forward-declared bases are now resolved
  correctly. (`1419608d`)

## Internal / build / parser changes

- Simplified the parser's detection of `:::` as a hotkey label. (`66236347`)
- Removed the now-redundant `NO_SUPPRESS_NEXT_UP_EVENT` mechanism from the hook engine,
  consolidating key-up suppression logic. (`a3b54b9f`)
- Minor cleanup of prefix key-up handling and removal of conflicting/stale comments in
  `hook.cpp`. (`0051e954`, `fe0da199`, `cd5fe32e`, `671e0e50`)
