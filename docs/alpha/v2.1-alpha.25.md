# AutoHotkey v2.1-alpha.25

**Released:** 2026-04-05
**Previous:** [v2.1-alpha.24](./v2.1-alpha.24.md)
**Next:** [v2.1-alpha.26](./v2.1-alpha.26.md)
**Upstream tag:** [`v2.1-alpha.25`](https://github.com/AutoHotkey/AutoHotkey/tree/v2.1-alpha.25)

## Overview

alpha.25 is a stability and compatibility release built around one new feature — `ahk_opt` inline WinTitle options — and a broad sweep of bug fixes across the hotkey engine, module system, window functions, DllCall, and GUI. The release also carries several internal cleanups (obsolete code removal, refactored WinGroup, simplified MsgBox timeout state) with no user-visible effect.

---

## New features

### `ahk_opt` — per-call WinTitle search options

A new `ahk_opt` criterion can appear anywhere in a WinTitle string and lets you override `DetectHiddenWindows`, `SetTitleMatchMode`, and `DetectHiddenText` for a **single call** without changing the global settings.

**Syntax:**

```autohotkey
WinExist("WinTitle ahk_opt Option1 Option2 ...")
```

**Supported option tokens** (case-insensitive, space-separated after `ahk_opt`):

| Token | Effect |
|---|---|
| `Hidden` or `Hidden1` | Detect hidden windows for this call |
| `Hidden0` | Ignore hidden windows for this call |
| `HiddenText` or `HiddenText1` | Detect hidden text for this call |
| `HiddenText0` | Ignore hidden text for this call |
| `1`, `2`, `3` | Title match mode (StartsWith, Contains, Exact) |
| `RegEx` | Title match mode: regular expression |
| `Fast` | Use fast title-find method |
| `Slow` | Use slow (but more thorough) title-find method |

`ahk_opt` can be combined freely with other `ahk_` criteria such as `ahk_class`, `ahk_exe`, and `ahk_id`. The global settings (`A_DetectHiddenWindows`, etc.) are **not modified**.

**Examples:**

```autohotkey
; Find a hidden Notepad window without touching DetectHiddenWindows globally.
hwnd := WinExist("Notepad ahk_opt Hidden 2")

; Combine ahk_class with ahk_opt (find taskbar even when hidden).
hwnd := WinExist("ahk_class Shell_TrayWnd ahk_opt Hidden")

; Use regex matching only for this one call.
hwnd := WinExist("ahk_exe explorer.exe ahk_opt Hidden RegEx")

; Global setting is unchanged after the above calls.
MsgBox("DetectHiddenWindows is still: " A_DetectHiddenWindows)
```

`ahk_opt` also works when a window group is involved (`ahk_group`). Invalid option tokens produce an error at runtime.

## Bug fixes

### Window functions

- **`WinExist("A",,,"ExcludeText")` now correctly applies exclusion.** Previously, windows with no controls were excluded unconditionally whenever an ExcludeText argument was present, regardless of whether the text matched. Fixed so that only windows whose control text actually matches ExcludeText are excluded.

- **`WinExist("", "Text")` no longer reads the title of every window.** The title-retrieval pass was redundant and had a measurable performance cost when the WinTitle argument is an empty string. It is now skipped.

- **Assertion failure for empty window titles** is no longer triggered in the internal window-matching code. This was an engine-level crash path that could be hit in edge cases involving empty title strings.

- **`ahk_opt hidden` now works correctly via `ahk_group`.** When a WinTitle with `ahk_opt Hidden` was resolved through an `ahk_group` criterion, the hidden-detection override was not being forwarded to the group enumeration. Fixed. Several other edge cases in option forwarding were also corrected in the same pass.

### Hotkeys

- **Key-up hotkeys now fire consistently when the key is used as both prefix and suffix.** When a key appears both as a prefix in a custom combo and as a suffix in an `up` hotkey, the up hotkey could silently not fire. Example that is now handled correctly:

  ```autohotkey
  a & b::MsgBox("combo")
  b & a::MsgBox("combo 2")
  a up::MsgBox("a released")   ; now fires reliably
  b up::MsgBox("b released")   ; now fires reliably
  ```

- **Custom combo hotkeys with neutral modifiers now work** (e.g. `Alt & Esc::`). Using the neutral form of a modifier key (`Alt`, `Ctrl`, `Shift`, `Win`) as the prefix key in a custom combo was broken since v2.0.22 (commit `15205f79`). This regression is fixed.

  ```autohotkey
  Alt & Esc::MsgBox("Alt+Esc combo")   ; works again
  ```

- **Key-up suppression now respects `SendLevel`.** Whether a key-up event is suppressed is now evaluated against the `SendLevel` at which the triggering key-down was sent. Keys sent at `SendLevel` 8 and above are treated as non-sent (i.e., suppression from lower-level hotkeys does not apply to them). This prevents layered remapping scripts from interfering with each other. Two example scenarios that are now handled correctly:

  ```autohotkey
  ; Example 1: hotkey sends itself — up should not be suppressed.
  #InputLevel 1
  Right::Send("{Right}")

  ; Example 2: swapped keys — each swap should not suppress the other's up event.
  #InputLevel 1
  RShift::RAlt
  RAlt::RShift
  ```

### Module system

- **`ModuleA.B` now initializes classes and imported modules on access.** Accessing a sub-object through a module reference could previously skip class or module initialization steps.

- **`A.B` where `B` is wildcard-imported into module `A` now resolves correctly.** This form previously failed silently.

- **Fixed crash when calling an unset global via a Module object.** Attempting to call an unset global that was referenced through a module object caused a crash; it now raises a proper runtime error.

- **`global g` in a function no longer conflicts with a prior `export global g` in the same module.** Declaring a variable as a plain global inside a function was incorrectly treated as a conflict when the same variable had already been exported at module scope.

- **Module initialization no longer changes the line reported by subsequent errors.** When a module was initialized mid-script, the error-reporting line counter could be left pointing at the wrong location. Example of the previous incorrect behavior:

  ```autohotkey
  ; Without the fix, a subsequent error points at the wrong line.
  x := unset        ; Error: should point here in calling code, not inside module init
  #module a
  #import __main {x}
  x()               ; Error correctly points here now
  ```

### DllCall

- **`DllCall` now rejects array classes for the return type instead of crashing.** Passing a struct array class (e.g. `POINT[3]`) as the return type argument caused a crash. A proper runtime error is now raised.

### GUI

- **`Gui().AddButton()` with no explicit width no longer causes a Critical Error on Windows 7.** The internal control-sizing calculation produced an invalid value on Windows 7 when the width was unspecified, triggering the OS-level critical error handler. Fixed.

### Error reporting

- **Some error messages were not pointing to the correct line.** A regression introduced around alpha.10 (`9274b6ed`) caused certain error messages to report the wrong source line. Fixed.

### Timer / MsgBox interaction

- **Timer threads can no longer interrupt `MsgBox` before the window is shown.** A timer callback could fire in the window between the `MsgBox()` call and the actual dialog becoming visible, which could trigger re-entrant code or other unexpected behavior. `MsgBox` now sets its state earlier so that timers see it as already active.

## Internal / build / parser changes

- **`Struct.Ptr.Prototype.__Value` consolidated into `Struct.Ptr`.** Previously, each struct class carried its own copy of the `__Value` accessor on its `Ptr.Prototype`. This was moved to the shared `Struct.Ptr` class. The change corrects a memory usage issue (the per-class copies were allocated on `SimpleHeap`, which cannot be freed).

- **WinGroup internals refactored.** `WinGroup.cpp` was cleaned up with no behavioral change: dead code removed, responsibilities realigned between `WinGroup` and `window.cpp`.

- **MsgBox timeout state simplified.** The internal representation of MsgBox timeout tracking was restructured to use a single global variable instead of the previous multi-flag scheme, reducing code size in `application.cpp` and `script2.cpp`.

- **Removed obsolete variable** in `script.cpp` (no behavioral change).

- **Removed obsolete declaration** in `script_object_bif.cpp` (no behavioral change).

- **`ahk_opt` option validation added.** Unknown tokens after `ahk_opt` now produce a runtime error rather than being silently ignored.
