# AutoHotkey v2.1-alpha.33

**Released:** 2026-10-03
**Previous:** [v2.1-alpha.32](./v2.1-alpha.32.md)
**Upstream tag:** [`v2.1-alpha.33`](https://github.com/AutoHotkey/AutoHotkey/tree/v2.1-alpha.33)

> Latest release in the v2.1-alpha series as of 2026-10-08. This fork also carries
> the upstream `alpha` commits through `47eabd41` (2026-10-07), listed at the end.

## Overview

Alpha.33 rounds out modules and structs: `#Import` works inside a function, module
objects support the reference operator, and a cluster of 32-bit struct and callback
bugs are fixed. Nothing here is breaking for x64 scripts.

## New features

### `#Import` inside a function

A function body may contain `#Import`. The imported names are scoped to that
function, so a helper can pull in a module without adding names to the file's
module.

```ahk
#Requires AutoHotkey v2.1-alpha.33
Area(r) {
    #Import Geometry {PI}
    return PI * r * r
}
```

### `Module.__Ref` (`&Module.Var`)

The reference operator now works on a module object's variables. `&Geometry.Count`
returns a virtual reference, so a module-level variable can be passed to a ByRef
parameter or a built-in output parameter without importing the name.

```ahk
#Import Geometry
Bump(&v) => ++v
Bump(&Geometry.Count)
```

## Fixes

- `a.b[c]` no longer crashes when `a.b` returns unset; it throws `UnsetError`.
- `ObjSetCapacity`, `ObjGetCapacity` and related functions throw a `TypeError`
  when the target is a `Struct` instead of corrupting it.
- 32-bit: `EditGetLine`, `ControlChooseIndex` and `ControlDeleteItem` work again
  (broken since alpha.24).
- 32-bit: `DllCall(..., Struct.Ptr, unset)` allocates the out-struct correctly.
- 32-bit: `Struct.Array` DllCall parameter types are marshaled correctly.
- 32-bit: typed callbacks with 64-bit numeric parameters read the right stack slots.

## Upstream `alpha` commits after the tag (through 2026-10-07)

- `#Requires` inside an `#Include` or inside a function never sets the enclosing
  module's language mode; only a `#Requires` at the module's own top level does.
- `NumPut` and `NumGet` accept the numeric type classes (`Int32`, `UInt16`,
  `Float64`, `IntPtr`, ...) in place of the type strings.
- `OnMessage` no longer crashes when more than 65536 monitors are registered.
- Message filtering removed for TreeView controls and for the ListView inside
  `FileSelect`; `DirSelect` now responds to the mouse while a timer runs.
- README, Issues template and FUNDING changes (not applicable to this fork's README).
