# AutoHotkey v2.1-alpha.30

**Released:** 2026-05-22
**Previous:** [v2.1-alpha.29](./v2.1-alpha.29.md)
**Upstream tag:** [`v2.1-alpha.30`](https://github.com/AutoHotkey/AutoHotkey/tree/v2.1-alpha.30)

> Latest release in the v2.1-alpha series as of 2026-05-22.

## Overview

Alpha.30 is the largest upstream release in the 2.1 series — 20 upstream commits from
Lexikos across four distinct themes: a new `Void` return type for native calls, three
breaking removals that complete the typed-property type-system cleanup, three parser
fixes that close long-standing ambiguities, and a cohesive sweep of bug fixes across
the Struct subsystem, `String()`, `StrGet()`, virtual refs, and GUI.

If your code uses any of `a?.()`, `a?.[]`, property type strings (`i32`, `u32`, …), or
untyped size-specifier properties (e.g., `buf: 32`), **migration is required before
running on alpha.30**. See the Breaking changes section for exact replacements.

---

## New features

### `Void` return type for `DllCall`, `ComCall`, and `CallbackCreate`

A new `"Void"` type token (case-insensitive, like all type tokens) can now appear as
the *return type* position in `DllCall` and `ComCall`, and as the return-type slot of a
`CallbackCreate` type array. It signals that the callee's return value should be
discarded entirely rather than being interpreted as an integer or pointer.

**Why use it?** Many Win32 functions are documented as returning `VOID`. Without this
token you had to accept a meaningless numeric result. With `"Void"` the expression
evaluates to unset (blank-unset), making intent explicit and preventing accidental use
of a fabricated return value.

```autohotkey
; Call MessageBeep and explicitly discard the return value.
DllCall("MessageBeep", "UInt", 0, "Void")

; ComCall equivalent — last arg is the return type.
; DllCall("lib\func.dll\SomeVoidFn", "Int", 42, "Void")

; CallbackCreate with a typed array: [paramType, ..., returnType]
; The "Void" element tells the thunk not to put anything in EAX/RAX.
cb := CallbackCreate(myHandler, , [Int32, "Void"])
```

`"Void"` is accepted only in the return-type position. Using it as a parameter type
remains an error.

## Breaking changes

All three removals below were prepared over the previous several alpha releases. Alpha.30
is the point at which the old forms stop parsing or loading. Update your code before
running on alpha.30.

---

### 1. `a?.()` and `a?.[]` removed — use `(a?)()` and `(a?)[]`

The shorthand "maybe-call" (`a?.()`) and "maybe-index" (`a?.[]`) syntax has been
removed. These forms were ambiguous: the `?.` token already means "maybe-property
access", so layering call and index syntax on top of it created a confusing grammar
edge case.

**Replacement:** Wrap the maybe-expression in parentheses first, then apply the call
or index operator to the result.

```autohotkey
; Before (alpha.29 and earlier):
; result := obj?.someMethod()   ; maybe-call
; item   := arr?.[idx]          ; maybe-index

; After (alpha.30):
callable  := () => 42
unset_fn  := unset

; (expr?) evaluates to unset if expr is unset, otherwise to expr itself.
; Applying () or [] to an unset value short-circuits to unset.
val1 := (callable?)()           ; => 42
val2 := (unset_fn?)() ?? "n/a"  ; => "n/a"

arr      := [10, 20, 30]
unset_a  := unset
item1 := (arr?)[2]              ; => 20
item2 := (unset_a?)[2] ?? "n/a" ; => "n/a"
```

**Scope of change:** `script.cpp` — parser removed 23 lines of special-case handling
for the `?.()` / `?.[]` tokens.

---

### 2. Property type strings (`i32`, `u32`, etc.) removed

String shorthands for primitive types inside `Struct` property declarations are no
longer accepted. You must now use the corresponding class name directly.

| Old string | Replacement class |
|------------|-------------------|
| `i8`       | `Int8`            |
| `i16`      | `Int16`           |
| `i32`      | `Int32`           |
| `i64`      | `Int64`           |
| `u8`       | `UInt8`           |
| `u16`      | `UInt16`          |
| `u32`      | `UInt32`          |
| `f32`      | `Float32`         |
| `f64`      | `Float64`         |
| `ptr`      | `IntPtr`          |

> Note: there is no `UInt64` primitive class. For 64-bit unsigned values use `Int64`
> and interpret the sign bit yourself, or store the value as two `UInt32` fields.

```autohotkey
; Before (alpha.29 and earlier):
; Struct Point { x: i32 / y: i32 }

; After (alpha.30):
Struct Point {
    x: Int32
    y: Int32
}

p := Point()
p.x := 7
p.y := 11
MsgBox("Point: " p.x ", " p.y "  size: " p.Size " bytes")
; => Point: 7, 11  size: 8 bytes
```

**Scope of change:** `MdFunc.cpp`, `MdType.h`, `CCallback.cpp`, `script.cpp`,
`script_object.cpp` — 66 lines of shorthand mapping removed.

---

### 3. Untyped typed properties (size specifier without a class) removed

The bare-integer form for reserving raw bytes inside a `Struct` — `fieldName: 32`
(32 raw bytes, no type class) — is no longer valid. The type system requires every
typed property to carry an explicit class.

```autohotkey
; Before (alpha.29 and earlier):
; Struct Packet { header: 8 / payload: 128 }
; ^^ reserved 8 bytes then 128 bytes with no type

; After (alpha.30):
; Option A: use Int8 fields for raw byte arrays.
Struct Packet {
    header:  Int8    ; single byte; repeat/array syntax covers longer runs
    payload: Int64   ; or use nested struct / Buffer alongside
}

; Option B: manage the raw region with a Buffer object outside the struct.
rawBuf := Buffer(128, 0)
```

**Scope of change:** `script_object.cpp`, `script_object.h` — 23 lines removed.

## Bug fixes

### Parser / load-time checks

- **Ambiguous `!a ?? b` and `b + a ?? c` are now caught at load time.**  
  Without explicit parentheses the precedence of `!` and `+` against `??` was
  undefined and could silently produce the wrong parse tree. The parser now emits a
  load-time error for these forms. Parenthesise to make intent explicit:

  ```autohotkey
  a := unset
  b := 42
  c := 100

  ; Ambiguous forms now rejected at load time:
  ;   !a ?? b        -- use !(a ?? b) or (!a) ?? b
  ;   b + a ?? c     -- use b + (a ?? c) or (b + a) ?? c

  val1 := !(a ?? b)       ; => false  (42 is truthy, !42 => false)
  val2 := b + (a ?? c)    ; => 142
  ```

- **`x?.%y%` is no longer a syntax error.** The maybe-property operator (`?.`)
  combined with a dynamic property name (`%y%`) was incorrectly rejected at parse
  time. It now works identically to `x.%y%` but short-circuits when the receiver is
  unset.

  ```autohotkey
  cfg := {theme: "dark", lang: "en"}
  key := "theme"
  MsgBox(cfg?.%key%)           ; => "dark"
  MsgBox((unset)?.%key% ?? "n/a") ; => "n/a"
  ```

- **Debugger breakpoints on fat-arrow (`=>`) lines with a block parent** are now
  handled correctly. Previously a breakpoint set on a line whose expression contained
  `=>` and whose direct parent node was a block caused incorrect behaviour.

### String and conversion

- **`String(x)` no longer crashes when `x.ToString()` returns no value.**  
  Previously `String(obj)` could crash the interpreter when the object's `ToString()`
  method returned without a value (i.e., fell off the end or executed `return`
  without an argument). Now `String()` cleanly propagates the missing return value:
  the result is unset, which you can default with `??` or catch as a normal
  "No value was returned" error.

  ```autohotkey
  class Silent {
      ToString() { }   ; returns nothing
  }

  result := String(Silent()) ?? "(no value)"
  MsgBox(result)   ; => "(no value)"
  ```

- **`StrGet(buf, 0)` now returns a `String`, not a number.**  
  Passing a zero length to `StrGet` used to slip through an early-exit path and
  return the raw numeric pointer value. It now always returns a (possibly empty)
  `String`, consistent with `StrGet`'s documented return type. Broken by alpha.28.

  ```autohotkey
  buf := Buffer(64, 0)
  StrPut("hello", buf, "UTF-16")
  zero := StrGet(buf, 0)
  MsgBox(Type(zero))          ; => "String"  (was "Integer" before)
  five := StrGet(buf, 5, "UTF-16")
  MsgBox(five)                ; => "hello"
  ```

### Struct / type system

- **`Struct.Ptr()` crash fixed.** Calling `Ptr()` on the `Struct` class object itself
  (not an instance) caused an access violation. Fixed.

- **`StructClass.Ptr().__Value := unset` now works.** Assigning `unset` through the
  `__Value` setter of a struct pointer was incorrectly rejected. Fixed.

- **`DllCall` now propagates exceptions thrown by output-arg `__Value` evaluation.**  
  When a struct-typed output parameter commits its value back via `__Value`, any
  exception raised inside that getter was previously swallowed silently. It now
  surfaces as a normal exception at the `DllCall` site.

  ```autohotkey
  ; If an output struct's __Value getter throws, the exception now
  ; reaches your try/catch as expected:
  try {
      DllCall("SomeFunc", "Ptr", myStructWithBadValue)
  } catch as e {
      MsgBox("Caught: " e.Message)
  }
  ```

- **Virtual ref assignments now permit `unset`.**  
  A function accepting a VarRef (`&var`) parameter can now assign `unset` through
  the ref, leaving the caller's variable uninitialised rather than storing `""`.

  ```autohotkey
  ClearOut(&out) {
      out := unset
  }

  x := "had a value"
  ClearOut(&x)
  MsgBox(IsSet(x))   ; => 0  (x is now unset)
  ```

- **`Class` objects now allow `Base` assignment.** Setting `.Base` on a class object
  was broken by alpha.28 and is now restored.

### GUI / COM

- **`TraySetIcon("HBITMAP:" handle)` without a trailing `*`** now works correctly.
  The bare `HBITMAP:` prefix form was broken.

- **`ControlGetItems` and `ControlGetChoice`** now correctly throw an exception when
  called on a Tab control, matching the documented behaviour.

- **`ComObjArray().__Enum()`** error reporting improved. If the internal enumerator
  creation fails, the error is now reported correctly rather than triggering undefined
  behaviour.

## Internal / build changes

These are upstream parser and runtime internals; no script-visible behaviour changes
beyond what is listed above.

- Removed ~113 lines of type-string and untyped-property mapping code from
  `MdFunc.cpp`, `MdType.h`, `CCallback.cpp`, `script.cpp`, `script_object.cpp`,
  and `script_object.h` as part of the type-string / untyped-property removals.
- Removed parser special-casing for `?.()` / `?.[]` in `script.cpp` (~23 lines).
- `DllCall.cpp` and `CCallback.cpp` updated to handle `"Void"` in the return-type
  slot; new `ARGTYPE_VOID` constant added to `script.h`.
