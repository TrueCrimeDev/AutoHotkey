# AutoHotkey v2.1-alpha.22

**Released:** 2026-03-15
**Previous:** [v2.1-alpha.21](./v2.1-alpha.21.md)
**Next:** [v2.1-alpha.23](./v2.1-alpha.23.md)
**Upstream tag:** [`v2.1-alpha.22`](https://github.com/AutoHotkey/AutoHotkey/tree/v2.1-alpha.22)

## Overview

Alpha.22 is the foundational **Struct** release. The new `Struct` keyword lets
scripts define C-compatible memory layouts with typed fields (`i32`, `u8`,
`uptr`, etc.), enabling direct DllCall integration without manual `NumGet`/
`NumPut` bookkeeping. Alongside Struct, this release adds a top-level
`DefineProp()` function, improves `Type()` and `IsSet()` for unset-parameter
patterns, aligns `export` fat-arrow syntax with v2.0 semantics, and fixes
several parser and module bugs.

---

## New Features

### `Struct` keyword

The `Struct` keyword declares a class whose instances occupy a contiguous block
of native memory. Each field is annotated with a primitive type specifier that
determines its size and signedness.

**Supported field types:**

| Specifier | C equivalent | Size |
|-----------|-------------|------|
| `i8`      | `int8_t`    | 1 byte |
| `u8`      | `uint8_t`   | 1 byte |
| `i16`     | `int16_t`   | 2 bytes |
| `u16`     | `uint16_t`  | 2 bytes |
| `i32`     | `int32_t`   | 4 bytes |
| `u32`     | `uint32_t`  | 4 bytes |
| `i64`     | `int64_t`   | 8 bytes |
| `u64`     | `uint64_t`  | 8 bytes |
| `iptr`    | `intptr_t`  | 4 or 8 bytes (pointer-sized) |
| `uptr`    | `uintptr_t` | 4 or 8 bytes (pointer-sized) |
| `f32`     | `float`     | 4 bytes |
| `f64`     | `double`    | 8 bytes |

**Basic usage:**

```autohotkey
#Requires AutoHotkey v2.1-alpha.22

Struct POINT {
    x: i32
    y: i32
}

pt := POINT()
pt.x := 100
pt.y := 200
MsgBox(Format("POINT({}, {}) — Type={}, Size={} bytes", pt.x, pt.y, Type(pt), pt.Size))
```

**Multi-field and mixed-size structs:**

```autohotkey
Struct RECT {
    left:   i32
    top:    i32
    right:  i32
    bottom: i32
}

rc := RECT()
rc.left := 0, rc.top := 0, rc.right := 1920, rc.bottom := 1080
MsgBox(Format("RECT({},{} to {},{}) — {} bytes",
    rc.left, rc.top, rc.right, rc.bottom, rc.Size))

Struct Color {
    r: u8
    g: u8
    b: u8
    a: u8
}

c := Color()
c.r := 255, c.g := 128, c.b := 0, c.a := 255
MsgBox(Format("RGBA({},{},{},{}) — {} bytes", c.r, c.g, c.b, c.a, c.Size))
```

**Nested structs:**

A field's type can be another `Struct` name. The nested struct is laid out
inline (not as a pointer).

```autohotkey
Struct NMHDR {
    hwndFrom: uptr
    idFrom:   uptr
    code:     i32
}

Struct NMCUSTOMDRAW {
    hdr:         NMHDR
    dwDrawStage: u32
    hdc:         uptr
    rc:          RECT
    dwItemSpec:  uptr
    uItemState:  u32
    lItemlParam: iptr
}

ncd := NMCUSTOMDRAW()
ncd.hdr.code   := -12   ; NM_CUSTOMDRAW
ncd.dwDrawStage := 1
ncd.rc.left    := 10
ncd.rc.top     := 20
MsgBox(Format("NMCUSTOMDRAW: hdr.code={}, rc.left={}, total {} bytes",
    ncd.hdr.code, ncd.rc.left, ncd.Size))
```

**DllCall integration:**

Struct instances pass directly as DllCall parameters using the struct class name
as the type string. DllCall now requires a proper `Struct` subclass for struct
parameters — arbitrary objects with a `DataPtr` property are no longer accepted
(see Breaking Changes).

```autohotkey
Struct SYSTEMTIME {
    wYear:         u16
    wMonth:        u16
    wDayOfWeek:    u16
    wDay:          u16
    wHour:         u16
    wMinute:       u16
    wSecond:       u16
    wMilliseconds: u16
}

st := SYSTEMTIME()
DllCall("GetLocalTime", SYSTEMTIME, st)
MsgBox(Format("Local time: {}-{:02}-{:02} {:02}:{:02}:{:02}",
    st.wYear, st.wMonth, st.wDay, st.wHour, st.wMinute, st.wSecond))
```

**Practical example — `GlobalMemoryStatusEx`:**

```autohotkey
Struct MEMORYSTATUSEX {
    dwLength:               u32
    dwMemoryLoad:           u32
    ullTotalPhys:           u64
    ullAvailPhys:           u64
    ullTotalPageFile:       u64
    ullAvailPageFile:       u64
    ullTotalVirtual:        u64
    ullAvailVirtual:        u64
    ullAvailExtendedVirtual: u64
}

ms := MEMORYSTATUSEX()
ms.dwLength := ms.Size
DllCall("GlobalMemoryStatusEx", MEMORYSTATUSEX, ms)
totalGB := ms.ullTotalPhys / (1024 ** 3)
availGB := ms.ullAvailPhys / (1024 ** 3)
MsgBox(Format("Memory: {:.1f} GB total, {:.1f} GB available ({}% used)",
    totalGB, availGB, ms.dwMemoryLoad))
```

Every `Struct` instance exposes a `.Size` property (total byte count) which is
useful when an API requires you to populate a `dwLength` or `cbSize` field
before the call.

### Automatic `Struct.Ptr` subclasses

Every struct class automatically gains a nested `.Ptr` class that provides a
**zero-copy view** into an existing block of memory at a given address. This
replaces the removed `StructFromPtr` function (see Breaking Changes).

The primary entry point is `StructName.At(ptr)`, which returns a `.Ptr`
instance overlaying the memory at `ptr`.

```autohotkey
; Confirm the auto-generated .Ptr class exists
MsgBox(POINT.HasOwnProp("Ptr") ? "POINT.Ptr exists" : "missing")
MsgBox(RECT.HasOwnProp("Ptr")  ? "RECT.Ptr exists"  : "missing")
```

**Typical pattern in a `WM_NOTIFY` handler:**

```autohotkey
OnMessage(0x4E, WM_NOTIFY)

WM_NOTIFY(wParam, lParam, msg, hwnd) {
    hdr := NMHDR.At(lParam)       ; zero-copy view at lParam
    if hdr.code = -12 {           ; NM_CUSTOMDRAW
        ncd := NMCUSTOMDRAW.At(lParam)
        ; Read/write ncd fields without any copying
    }
}
```

`.At(ptr)` is the canonical way to reinterpret a raw pointer (e.g. from a
callback `lParam`) as a typed struct, with no allocation or data copy.

### `DefineProp()` top-level function

A new built-in function `DefineProp(obj, name, descriptor)` mirrors the
existing `obj.DefineProp(name, descriptor)` method. The advantage of the
free-function form is that the target object can be dynamic or passed through
a function parameter without needing to call a method on it.

```autohotkey
; Getter / setter pair on a plain object
obj := {}
DefineProp(obj, "Name", {
    Get: (this) => this._name ?? "unnamed",
    Set: (this, value) => this._name := value
})
obj.Name := "alpha22"
MsgBox(obj.Name)   ; alpha22

; Read-only computed property
coords := { x: 3, y: 4 }
DefineProp(coords, "Magnitude", {
    Get: (this) => Sqrt(this.x ** 2 + this.y ** 2)
})
MsgBox(Format("Magnitude: {}", coords.Magnitude))   ; 5.0

; Apply to a class prototype
class Counter {
    __New() => this._count := 0
}
DefineProp(Counter.Prototype, "Count", {
    Get: (this) => this._count,
    Set: (this, value) => this._count := Max(0, value)
})
ctr := Counter()
ctr.Count := 42
MsgBox(Format("Count: {}", ctr.Count))   ; 42
```

**Factory pattern** — a helper that adds a property to any object:

```autohotkey
AddTimestamp(target, propName) {
    DefineProp(target, propName, {
        Get: (*) => FormatTime(, "yyyy-MM-dd HH:mm:ss")
    })
}
record := {}
AddTimestamp(record, "CreatedAt")
MsgBox(record.CreatedAt)
```

### `Type()` returns `"unset"` for omitted parameters

`Type()` now returns the string `"unset"` when called with no argument or when
its parameter is an omitted optional. Previously this threw an error. The change
enables type-dispatch patterns that cleanly handle the missing-value case.

```autohotkey
MsgBox(Type())      ; "unset"
MsgBox(Type(42))    ; "Integer"
MsgBox(Type("hi"))  ; "String"
MsgBox(Type([]))    ; "Array"

; Type-dispatch that handles unset cleanly
FormatValue(val?) {
    if !IsSet(val)
        return "(unset) — Type() = " Type()
    switch Type(val) {
        case "Integer", "Float": return Format("Number: {}", val)
        case "String":           return Format('String: "{}"', val)
        case "Array":            return Format("Array[{}]", val.Length)
        default:                 return Format("Object: {}", Type(val))
    }
}

MsgBox(FormatValue(100))    ; Number: 100
MsgBox(FormatValue("test")) ; String: "test"
MsgBox(FormatValue())       ; (unset) — Type() = unset
```

### `IsSet()` accepts unset expressions

`IsSet()` can now receive an optional parameter directly without wrapping it in
a variable assignment. A companion fix ensures `IsSet(p)` correctly returns `0`
when `p` is an unset virtual reference.

```autohotkey
CheckValue(val?) {
    if IsSet(val)
        MsgBox(Format("val is set: {}", String(val)))
    else
        MsgBox("val is unset")
}

CheckValue("hello")   ; val is set: hello
CheckValue()          ; val is unset

; Multi-optional parameter pattern
SmartFunc(a, b?, c?) {
    parts := [Format("a={}", a)]
    parts.Push(IsSet(b) ? Format("b={}", b) : "b=unset")
    parts.Push(IsSet(c) ? Format("c={}", c) : "c=unset")
    result := ""
    for p in parts
        result .= (A_Index > 1 ? ", " : "") p
    MsgBox(Format("SmartFunc: {}", result))
}

SmartFunc("x", "y", "z")   ; a=x, b=y, c=z
SmartFunc("x", "y")         ; a=x, b=y, c=unset
SmartFunc("x")              ; a=x, b=unset, c=unset
```

## Changes

### `export a() => b` is now a function call statement

In a module file, the expression `export a() => b` is now parsed as a function
**call** to `export()` (matching the behavior of plain v2.0 code), not as an
exported fat-arrow function definition. This aligns with v2.0 semantics where
`a() => b` on its own line is always a call, not a definition.

**Migration:** use block syntax for all exported functions:

```autohotkey
; Before alpha.22 — parsed as an exported fat-arrow definition:
export MyDouble(x) => x * 2      ; no longer works as intended

; After alpha.22 — must use block syntax:
export MyDouble(x) {
    return x * 2
}
```

## Breaking Changes

### `StructFromPtr` removed

The `StructFromPtr` built-in function has been removed. Use the auto-generated
`.Ptr` subclass and its `.At(ptr)` method instead.

```autohotkey
; Before alpha.22:
; pt := StructFromPtr(POINT, somePtr)

; After alpha.22:
pt := POINT.At(somePtr)
```

### DllCall no longer accepts arbitrary objects for struct parameters

The `DataPtr` fallback that previously allowed any object with a `DataPtr`
property to be passed as a struct-typed DllCall parameter has been removed.
DllCall now requires a proper `Struct` subclass instance. Scripts that were
using hand-rolled classes with a `DataPtr` property must migrate to `Struct`.

```autohotkey
; Before alpha.22 — worked via DataPtr fallback:
; class OldPoint {
;     DataPtr => this._buf.Ptr
;     ...
; }

; After alpha.22 — must be a real Struct:
Struct POINT {
    x: i32
    y: i32
}
pt := POINT()
DllCall("...", POINT, pt)
```

### `export a() => b` syntax change (see Changes section)

Scripts with exported fat-arrow functions must migrate to block syntax. See the
Changes section above for the migration pattern.

## Bug Fixes

- **Fixed `!~=` operator** — The not-regex-match operator (`!~=`) was producing
  incorrect results and is now fixed.

- **Fixed wrong module being reopened at end of file** — A parser bug caused the
  wrong module to be reopened when a module file ended, potentially misattributing
  declarations.

- **Fixed `#Import __Init` failing when there are no sub-modules** — `#Import __Init`
  no longer throws when the imported module has no sub-modules.

- **Fixed `DllCall(... "str", &var:={} ...)` misdetected as error** — A false
  positive in the DllCall error checker was incorrectly flagging a `str` parameter
  paired with a freshly-created by-reference variable as an error.

- **Fixed `IsSet(p)` for unset virtual references** — `IsSet(p)` now correctly
  returns `0` when `p` is an unset virtual reference rather than returning a
  truthy value.

## Internal / Build / Parser Changes

- **Struct keyword parsing** — `script.cpp` gained a new Struct definition
  parser path; `script_object.cpp` implements the Struct class and automatic
  `.Ptr` subclass generation.
- **DllCall struct handling refactored** — `DllCall.cpp` was significantly
  reworked to remove the `DataPtr` fallback and add native Struct pass-by-value
  support; automatic `.Ptr` class generation for DllCall pointer parameters also
  landed here.
- **`DefineProp` BIF registered** — `script_object_bif.cpp` registers the new
  free-function form alongside the method form.
- **`export` fat-arrow fix** — One-line change in `script.cpp` restores the
  v2.0 parsing rule for `export func() => expr`.
