## Overview

Alpha.34 tightens structs and property descriptors: anonymous unions, `Struct.Array`
decaying to `Struct.Ptr`, `Clone` refusing typed properties, and an `Enumerable`
flag that hides a property from `Props` and the debugger. The v2.0 branch merge brings
the `FileSetTime` and `NumPut`/`NumGet` changes.

## New features

### `Enumerable: false` in a `DefineProp` descriptor

A property defined with `Enumerable: false` is skipped by `Props()` and by the
debugger's property listing. It is still an own property: `OwnProps()`,
`HasOwnProp` and `ObjOwnPropCount` keep reporting it, and it reads and writes as
usual.

```ahk
#Requires AutoHotkey v2.1-alpha.34
o := {}
o.DefineProp("shown", {Value: 1})
o.DefineProp("hidden", {Value: 2, Enumerable: false})
for name in o.Props()      ; shown
for name in o.OwnProps()   ; hidden, shown
```

### Anonymous unions in structs

A struct class may contain a union without naming it; its members are accessed
directly on the struct.

### Numeric type classes in `NumPut`/`NumGet`

`NumPut(Int32, v, buf)` and `NumGet(buf, Int32)` accept the numeric type classes in
place of the type strings (from the v2.0 branch; this fork already carried the
commit as a post-alpha.33 change).

## Changes

- `Clone` throws `TypeError` when the object has typed properties, instead of
  producing a broken copy.
- Typed properties and `DllCall` let a `StructClass.Array` decay to
  `StructClass.Ptr`.
- `NumericClass.Ptr` behaves like the other struct pointer classes.
- `a.%b?% ?? c` short-circuits like `%r?% ?? c` instead of invoking the default
  property.
- `DefineProp` validates the descriptor: an unknown key, or `Value` combined with
  `Get`/`Set`/`Call`, throws `ValueError` "Parameter #2 of
  Object.Prototype.DefineProp is invalid."
- `#Requires` inside a function or an `#Include`d file never changes the current
  module's compatibility mode for global code (`08beacf1`, `47eabd41`).
- `FileSetTime` is more reliable under restricted permissions and file locks
  (PR #358).
- Message filtering removed for TreeView controls and `FileSelect` dialogs
  (reverts a v1.0.44.11 workaround that broke `DirSelect` on current Windows).
