# AutoHotkey v2.1-alpha.27

**Released:** 2026-04-19
**Previous:** [v2.1-alpha.26](./v2.1-alpha.26.md)
**Next:** [v2.1-alpha.28](./v2.1-alpha.28.md)
**Upstream tag:** [`v2.1-alpha.27`](https://github.com/AutoHotkey/AutoHotkey/tree/v2.1-alpha.27)

## Overview

This release is entirely focused on typed/struct objects — the in-progress value-type system that
lets AHK classes describe their own memory layout. The work spans three inter-related themes:

1. **Memory consolidation** — nested struct objects are now embedded directly in the outer
   allocation rather than being separately heap-allocated and cross-linked via an index array.
2. **Lifecycle correctness** — three destructor / cleanup bugs are fixed (arrays of structs,
   Ptr classes with fieldless targets, and general Base-release ordering).
3. **Restriction tightening** — `a.Base := b` is now an error when either side already has typed
   properties, preventing silent corruption of an already-initialized struct layout.

All changes are in `source/script_object.cpp` and `source/script_object.h`; there are no AHK
language-surface changes visible to scripts that do not use typed properties.

## Changes

### Nested struct objects merged into a single allocation

Previously each struct instance that contained nested struct fields required separate heap
allocations for each nested object, cross-linked through an `mNested` pointer array. The outer
object held `mNested[0]` as a back-reference ("outer") and `mNested[1..n]` for each nested field.

`Object::mNested` is replaced by a single `Object *mOuter` back-pointer. Nested objects are now
embedded directly in the memory block immediately before the raw data suffix, in definition order.
`StructInfo::nested_count` (the count of nested object slots) is replaced by
`StructInfo::nested_object_size` (the total byte count reserved for those embedded objects).

Key consequences for script authors:
- Struct instances use fewer heap allocations, reducing memory overhead and GC pressure.
- Pointer-type fields (`Ptr` classes) use `sizeof(Object*)` bytes in the nested region; non-pointer
  nested structs use `object_size + nested_object_size + sizeof(void*)` bytes each.
- The `Initialize()` method no longer accepts an `aOuter` parameter; outer-object relationships are
  established through the allocation layout instead.

Internal rename summary:

| Old | New |
|---|---|
| `Object::mNested` (array) | `Object::mOuter` (single pointer) |
| `StructInfo::nested_count` | `StructInfo::nested_object_size` |
| `TypedProperty::object_index` | `TypedProperty::object_offset` |
| `Object::CallNestedDelete()` | `Object::CallMetaDelete()` |

The combined `CallMetaDelete()` now calls `__Delete` first and then destructs all nested objects,
replacing the previous two-pass approach.

### Ordered linked list of typed properties on Prototype

`StructInfo` now maintains a doubly-linked list (`first_field` / `last_field`, each node also has
`prev_field`) of all `TypedProperty` instances defined on that prototype. Previously the code had
a TODO comment noting this was needed and worked around it with a two-pass field-scan at
instantiation time.

Benefits:
- `NestedNew()` iterates the list directly instead of scanning all inherited fields on every
  construction.
- `Object::~Object()` iterates the list to `delete` each `TypedProperty` when the class prototype
  is finalized (destructor now correctly checks `ClassPrototype` flag rather than
  `StructInfoInitialized`; see bug fix below).
- `DefineTypedProperty()` now asserts that it is only called on a class prototype and always
  appends to the tail of the list.

### `a.Base := b` is now invalid when typed properties are involved

Two additional guards are added to `Object::SetBase()`:

1. **Self guard** (`CanSetBase()` no-arg overload): fails if the target object has already been
   initialized from its current Base (flag `StructInfoInitialized`) or if it is a struct instance
   (`DataIsSuffix` / `DataIsSuffixPtr` flags are set).
2. **New-base guard** (`CanSetBase(Object*)` overload): fails if the proposed new base has a
   non-zero struct data size (i.e. it defines typed properties).

Both paths throw a `ValueError`. Scripts that previously assigned `Base` after typed properties
were defined were producing silent memory-layout corruption; this is now a hard error.

```autohotkey
; This now throws ValueError instead of silently corrupting layout:
; a.Base := b  ; if a or b has typed properties
```

### `Object::mData` removed; data uses suffix flags

`Object::mData` (a plain `void *` member used to hold a struct's raw bytes) is removed. The struct
data is now accessed exclusively through the suffix layout indicated by two new `mFlags` bits:

- `DataIsSuffix` — raw data immediately follows the `Object` header (and any nested-object block).
- `DataIsSuffixPtr` — a single `void *` follows the header (and nested-object block) and points to
  the real data (used by Ptr-wrapper objects).

Helper methods `HasData()`, `DataPtr()`, `StructSize()`, and `LockStructSize()` are added to
`Object` for uniform access to the data region. `CreateStruct()`, `CreateStructPtr()`, and related
factory functions are updated to compute the correct allocation size including the nested-object
block.

### `StructInfo` carries constructor and size

`StructInfo` now stores:
- `NewObjectProc create` — the constructor function pointer for instances of this struct type.
- `size_t object_size` — the compiled byte-size of the `Object` header (so the layout math does
  not depend on a compile-time `sizeof(Object)` in callers).
- `bool IsPointerType()` — returns `true` when `pointed_class` is set and `item_count` is zero.
- `size_t SizeWhenNested()` — returns the bytes this struct consumes when embedded as a nested
  field in another struct.

Previously these were scattered in `script.h` and computed ad-hoc at call sites.

## Bug fixes

- **Structs in arrays not being destructed** — `~Object()` and `CallMetaDelete()` now correctly
  determine element type from `nested_object_size / item_count` instead of re-querying the element
  class prototype. This fixes cases where array items with nested objects were not having their
  destructors called, leaving the `Base` reference un-released. (`e6ed8924`)

- **Ptr class not deleted when target struct has no fields** — The destructor previously checked
  `StructInfoInitialized` to decide whether to walk the `StructInfo`. For Ptr-class prototypes
  whose target has no fields, `StructInfoInitialized` was never set, so `first_field` was never
  iterated and the `TypedProperty` objects were leaked. The check is now `ClassPrototype`, which is
  set on all class prototypes. (`74db0a0b`)

- **Instantiation crash when `.Prototype` is a plain Object** — Calling a class whose `.Prototype`
  is a plain `Object` (not a `Class.Prototype`) threw an unguarded null-dereference. The fix reads
  the `Prototype` own property with `GetOwnPropObj` and treats it as a prototype only when it is
  actually of type `Object` (i.e. the `IsOfType` check passes), otherwise the base-check is
  skipped rather than crashing.

  ```autohotkey
  ; Previously crashed; now works:
  c := Class()
  c.Base := Object
  c.Prototype := {}
  i := c()
  MsgBox("Instance created: " Type(i))
  ```
  (`281fbb8d`)

## Internal / build / parser changes

- **x86 warning fixed** — An implicit narrowing conversion of `index * nested_size` (where `index`
  is a signed 32-bit value) was corrected to `(size_t)index * nested_size`, silencing a compiler
  warning in 32-bit builds. (`c37db7eb`)

- `Object::NestedSparseInit(ResultToken&)` (the no-property overload) is removed; all call sites
  now use the `(ResultToken&, TypedProperty&, UINT_PTR)` overload. (`6979d3ad`)

- `GetBoxedPointer` / `SetBoxedPointer` parameter `aCacheIndex` renamed to `aNestOffset` to
  reflect that it now carries a byte offset into the nested-object block rather than an array
  index. (`6979d3ad`)
