> 2026-11-12 (branch `m1/upstream-alpha38`, merge commit `c47c4c8b`).

## Overview

Alpha.38 is a Struct and module release. Structure definitions stay *open*
until something needs their layout, so two structs can reference each other
in either order. `Struct.At` and `ObjCreateWithDataPtr` take a `Buffer` and
accept any address. `ObjGetDataPtr` returns `unset` where it threw. Three
module bugs are fixed, along with two regressions from alpha.37 that the
fork had already patched. Eighteen upstream commits after `279247ee`,
including a `v2.0` merge (`fc0479fa`).

`upstream/alpha` is five commits past the tag (`42ddbabc`: function
definitions separated from the outer line list, nested-function import
resolution, `WinGetTransparent` returning `""`). They are not merged here.

## Changed

### Open structures

(`ad5cfae6`, `afde2333`) A struct's typed-property offsets and size are no
longer calculated in `DefineProp`. Each prototype's structure stays open, and
can take more typed properties, until one of these closes it:

- an instance or boxed pointer is constructed;
- a structure that contains or extends it is closed;
- `ObjGetDataSize` is called on the prototype;
- the class is a `DllCall`, `ComCall` or `CallbackCreate` parameter or return type.

A struct still cannot contain itself, but two structs can now refer to each
other through a pointer in either definition order:

```autohotkey
struct S1 {
    P1 : S2.Ptr
}
struct S2 {
    P2 : S1          ; alpha.37: "Parameter #3 invalid." while initializing S1
    P3 : Int32
}
```

Visible effects:

- `ObjGetDataSize(Proto)` closes the structure and returns the padded size. For
  `{a : Int32, b : Int8}` it returns 8 before any instance exists; alpha.37
  returned the unpadded 5 until an instance was created.
- `DefineProp` on a closed structure throws `Error` "Cannot add typed
  property." Alpha.37 accepted it silently.
- `DefineProp` rejects a `Pack` other than 0, 1, 2, 4 or 8 (`ValueError`).
  Alpha.37 accepted `Pack: 3`.
- `GetOwnPropDesc` on a typed property reports `Pack` when a non-zero value was
  given. While the structure is open, it reports `Offset` only when one was
  requested, exactly as requested, so a name such as `"a"` stays a name.
  After the structure closes, it reports the calculated offset.
- An invalid descriptor in `DefineProp` now throws the generic `ValueError`
  "Parameter #2 invalid." ("#3" for the function form) with an empty `Extra`.
  Before, it threw "Parameter #2 of Object.Prototype.DefineProp is invalid."
  with `Extra` "Object". `What` still names `Object.Prototype.DefineProp`.

### `Struct.At` and `ObjCreateWithDataPtr` take a `Buffer`

(`802c49c9`) Either function accepts an object with a `Ptr` property in place
of an address. The view keeps that object alive, so a view of a function's
local `Buffer` stays valid after the function returns. An object without
`Ptr` throws `PropertyError`. In alpha.37, `At(buf)` threw "Parameter #1 of
Struct.At is invalid." and `ObjCreateWithDataPtr(S, buf)` used the object as
the address, exiting 11 "Invalid memory read/write." on the first field read.

```autohotkey
buf := Buffer(8, 0)
pt := POINT.At(buf)          ; pt.Ptr = buf.Ptr; buf lives as long as pt
```

### `StructClass.At` permits addresses below 65536

(`2042a5e7`) `S.At(0)`, `S.At(100)` and `UInt16.At(32516)` (the
`IDI_INFORMATION` resource ID) return views. `ObjCreateWithDataPtr(S, 100)`
is accepted too. Nothing is dereferenced until a field is read. Before, both
functions threw a parameter error for any address below 65536 (except 0 for
`ObjCreateWithDataPtr`).

### `ObjGetDataPtr` returns `unset`

(`d7353438`) For an object without structured data (`{}`, `[]`, `Map()`, a
prototype), `ObjGetDataPtr` returns `unset` instead of throwing `Error`
"Failed". In v2.1 mode a plain assignment of that result throws `UnsetError`,
so test it with `IsSet(ObjGetDataPtr(x))` or `ObjGetDataPtr(x) ?? 0`. A
non-object still throws `TypeError`.

## Fixes

- User-defined `Ptr` subclasses are constructed (`8b47614d`), so a field whose
  type is `Class(X.Ptr)` with its own `__Value` getter reads through that
  getter. Alpha.37 returned the pointed-to `X` instance. Subclassing `Ptr`
  requires `Class(X.Ptr)` for now; `class Y extends X.Ptr` is not accepted.
- `v := imported` runs the imported module first (`9ff3606b`). Modules run in
  reverse order of creation, so a later module's body can read an earlier
  module's variable before that module has run. Alpha.37 threw "This global
  variable has not been assigned a value." on a direct assignment, although
  other expressions already ran the module.
- A module run early by a reference inside a function no longer runs in that
  function's context (`c4d4137f`). `A_ThisFunc` in the module body was the
  calling function's name.
- A function's `#Import M {*}` takes precedence over a global wildcard import,
  whatever order the two `#Import` lines appear in (`41c751bc`). This applies
  to nested functions too. In alpha.37 a global `#Import` written after the
  function shadowed the function's own import.
- `a.b()` shows one error, not two, when the getter `a.b` throws
  (`1e55d515`). See the fork notes.
- `CallbackCreate` accepts a struct class with inherited fields and none of
  its own (`51547074`). See the fork notes.
- Undefined behaviour when constructing the struct for a callback's return
  value fails (`1fcc195f`). An uninitialized pointer was copied from. Not
  observable here: a struct whose `__New` throws is reported and the thread
  ends cleanly on both alpha.37 and alpha.38.
- From `v2.0` (`d21d44d5`): `Hotkey` `On`/`Off`/`Toggle` work on AltTab
  hotkeys again. Not exercised here.
- `ee029f90` (rebasing any prototype without typed definitions) was reverted
  by `9f0fc01d` before the release. No net change.

## Fork notes

- **Seven alpha.38 regressions, fixed in this build (2026-11-12, `b2885254`, `e474e616`, `07fa54d7` and `e13b80d8`):**
  Copilot's review of the fork's merge PR (#35) found them in the
  open-structure commits, and each was reproduced on the unfixed merge build
  `c47c4c8b`. A struct that contains itself by value (directly, mutually,
  through an array such as `S[2]`, or through its base) was accepted, and
  constructing it corrupted the heap (exit 127 or 139). It is now an invalid
  struct: `S()`, `S.At(buf)` and `ObjCreateWithDataPtr` throw `TypeError`
  "Invalid struct.", where alpha.37 rejected the field in `DefineProp`.
  `{Type: ComValue(3, 0)}` in `DefineProp` exited 11; it throws `ValueError`
  again. A `Class(Int32)` field dropped its class, so it read as `""` and its
  `__Value` never ran; it reads as on alpha.37. `GetOwnPropDesc` lost an
  `Offset` naming a field that sorts after the one described; it is kept now.
  Copilot's second review added two: a struct derived from an invalid one
  kept a nonzero size, so `CallbackCreate` accepted it (now size 0), and a
  module's wildcard re-export (`#Import Export C {*}`) was looked up with
  the calling function's imports (`41c751bc`), so a function importing `D`
  and then `B` read `D`'s `X` instead of `C`'s. The third review found that
  an array class such as `Int32[2]` accepted extra typed fields until first
  use (`afde2333`), which moved element 2 to offset 6. It refuses them again,
  as alpha.37 did. The fifth found `NumGet(buf, N)` accepting a
  `Class(Int32)` subclass as `Int32` until its layout closed and rejecting it
  afterwards. `NumGet`/`NumPut` now close the class first, as `DllCall`
  does, so such a subclass is always rejected; alpha.37 accepted it until
  the class was instantiated. Another finding, a nested function in an import-free function missing a
  global wildcard import (`41c751bc`), is upstream's own post-tag fix
  `c727bdf0`, cherry-picked. `qa/tests/test_alpha38.ahk` section 9 pins all
  of them. The report is
  [`docs/upstream/alpha38-regressions.md`](../upstream/alpha38-regressions.md).
- **Merge conflicts were in code the fork had patched.** Upstream rewrote
  `Object::CreateStructPtr` (`Create(aBase, si, ...)` and
  `StructInfo::DataSuffix`). The rewrite places the data pointer after
  `object_size` and sets `CannotOwnProps` from the base class before
  construction. That covers the fork's alpha.36 fixes `a41db9a1` (pointer
  written over a native subclass's fields) and `f24c23d1` (struct views
  owning properties), so upstream's version was taken. Upstream's
  `CallProperty` (`1e55d515`) and `GetStructCallbackArgInfo` (`51547074`)
  fix two of the five alpha.37 regressions the fork fixed in `a911f73d`, and
  were taken too. `test_alpha36.ahk` sections 3 and 7 and `test_alpha37.ahk`
  section 9 still pass on x64 and Win32.
- **Fork-only fixes kept:** the `NumPut` per-pair `num_size` reset, the Win32
  `unset` pointer parameter as one pointer-sized slot, and the
  `MdType::Array` exclusion in `CallbackCreate`'s `param_slot_count` and stub
  (an array parameter is one pointer slot). Upstream has not changed these.
  The last one now uses upstream's `StructSize()`, which is safe because
  `GetStructCallbackArgInfo` closes the structure first.
- **Factory signature:** `ee8080f8` changed native class factories from
  `create(size_t suffix)` to `ctor(void *p)`, with the caller allocating.
