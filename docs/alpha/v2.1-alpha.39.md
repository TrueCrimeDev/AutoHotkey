## Overview

Alpha.39 is a fix release. Function definitions now live in their own line
lists, which fixes function definition expressions under `if`/`else` and
changes what error dialogs and `ListLines` show. The rest fixes alpha.38's
struct and module regressions and a few small bugs. Twenty-three upstream
commits after `afde2333`, including a `v2.0` merge (`e42bce1b`).

## Changed

### Function definitions are separate from the outer line list

(`1c1994e1`, `42ddbabc`, `7db739be`) Each function body is unlinked from the
code around it while the script loads. A body reached during execution of
the outer block no longer has to be skipped at runtime, and is not added to
`ListLines`. Error dialogs no longer show lines from outside the current
function. `42ddbabc` fixes the links left by consecutive definitions
(upstream #370), and `7db739be` makes breakpoints search the separate lists,
including inside `#Module`s.

`_ScriptGetLines` walks the same links. Around a line inside a function its
range stops at the function's braces; a range outside a function skips over
the body:

```autohotkey
a := 1
F() {
    x := 1
    y := 2
}
b := 2
for l in _ScriptGetLines(A_LineFile, 1, 2)
    Print(l.Number)   ; 1, 6, 7 (alpha.38: 1, 2, 3)
```

## Fixes

- Function definition expressions are allowed under `if`/`else`/etc.
  (`1c1994e1`). alpha.38 raised "Unexpected function" at load time.
- `#Import` resolution in nested functions which don't use `#Import`
  (`c727bdf0`; the fork had cherry-picked it for alpha.38).
- `WinGetTransparent` returns an explicit `""` rather than no value
  (`f3291c14`). Under a v2.1 `#Requires`, alpha.38 threw `UnsetError`.
- Incorrect line display or a crash with consecutive function definitions
  where one raises a load-time error (#370, `42ddbabc`).
- The alpha.38 struct regressions #371-#374 and #376-#380, the wildcard
  re-export lookup #375, and the `&Module.Var` reference count #381. Each is
  the fork's own patch, applied unchanged.
- Default `Gui` font size when the current DPI differs from the logon DPI
  (`768d9bdc`).
- Through the `v2.0` merge: the debugger corrupting large `property_value`
  results (`b71f5841`), debugger hangs in `source` without a line range and
  on an abrupt disconnect (`a8b46df6`, `68c4258d`), RegEx crashes on invalid
  UTF-16 (`b9968dfc`), and two `Format` overruns (`2f2dcfdb`, `9acf14d7`).

## Fork notes

- **Same code as PR #39.** `768d9bdc` is the commit merged in `ca5b713b`;
  only the version string changed afterwards.
- **Lines inside functions.** The fork's `Script::GetLine` and coverage
  walked only the module line lists, so after `1c1994e1` `_ScriptGetLines`
  found nothing inside a function, an uncaught error made inside a function
  was reported at its throw line, and `/Coverage` lost every line inside a
  function. `ec2f18d9` walks each function body too.
- **Merge conflicts.** `Debugger.cpp` kept the fork's transport code (its
  `Recv` already treats a 0-byte read as a disconnect, as `68c4258d` does);
  `interop.cpp` took upstream's rewrite of the `NumGet` fix for #377.
- `qa/tests/test_alpha39.ahk` (5 asserts) pins sections 1-4 above; four of
  them fail on the alpha.38 engine `a6763d81`, and the fifth pins
  `ec2f18d9`. The struct and module fixes stay pinned by
  `test_alpha37.ahk` section 9, `test_alpha38.ahk` sections 9 and 10, and
  `test_alpha33.ahk`.
- Verified on `560b1f7e`, x64: console gate 17/17, qa 1045/1045 across 21
  files, `tools/check_all.py` 119/119. Win32: qa 1045/1045. CI runs
  43725340167 and 43725613020 passed every job on the merge (PR #39).
