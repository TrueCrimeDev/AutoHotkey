# AutoHotkey v2.1-alpha.35

**Released:** 2026-10-11
**Previous:** [v2.1-alpha.34](./v2.1-alpha.34.md)
**Upstream tag:** [`v2.1-alpha.35`](https://github.com/AutoHotkey/AutoHotkey/tree/v2.1-alpha.35)

> Latest release in the v2.1-alpha series as of 2026-10-12. Merged into this fork on
> 2026-10-12 (branch `m1/upstream-alpha35`), together with alpha.34.

## Overview

Alpha.35 makes `Map` and `Array` strict about key and index types in v2.1 mode and
replaces the library search logic for `#Include <Name>` and `#Import` with a search
path that follows the including file, plus an `AhkLibPath` environment override.
Scripts in v2.0 mode (no `#Requires AutoHotkey v2.1-...` at the top level) keep the
old behaviour.

## Changes in v2.1 mode

### `Map` rejects `Float` keys

`m[1.5] := x` throws `TypeError` "Expected an Integer but got a Float." A string
`"1.5"` is still a valid key. In v2.0 mode a Float key is accepted as before.

### `Array` rejects bad index types

`arr[1.0]` and `arr[""]` throw `TypeError` "Invalid index." (v2.0 mode: `1.0` is
accepted and `""` throws `IndexError`). Numeric strings such as `"1"` are still
converted to integers.

### `#Include <Name>` and `#Import` search path

Reference: [Script Library Folders / Search Path](https://www.autohotkey.com/docs/alpha/Scripts.htm#lib).

The folders searched, in order:

1. the directory of the including file (`A_LineFile "\..\"`, v2.1 mode only)
2. the current module's directory plus `\Lib\`
3. `A_ScriptDir "\Lib\"` (local library)
4. `A_MyDocuments "\AutoHotkey\Lib\"` (user library)
5. the directory of the running `AutoHotkey.exe` plus `\Lib\` (standard library)

The underscore has no special meaning in v2.1 mode: `#Include <A_B>` looks for
`A_B.ahk` (or `A_B.txt.ahk`) only, and fails with "Script library not found." when
there is none. In v2.0 mode it still falls back to `A.ahk`.

The `AhkLibPath` environment variable, when set, replaces the default list. The
user and standard libraries are then searched only if the variable names them.

### `#Import`

`Export` is rejected inside a function (it was already meaningless there).

## Fork notes

- **Upstream bug, fixed in this build (2026-10-12):** `Script::GetSearchPath`
  (`source/script_module.cpp`) set its duplicate-check pointer before the
  directory existence check, so once an entry did not exist (typically the first
  one, `Lib`, for a script with no `Lib` folder) every later entry, including the
  user library, the standard library and all of `AhkLibPath`, was silently
  dropped and `#Include <Name>` failed with "Script library not found." The fork
  assigns the pointer only for a kept entry; `qa/tests/test_alpha35.ahk` section 6
  pins it, and `docs/upstream/alpha35-searchpath-last-dir.md` holds the report.

- Merge commit on 2026-10-12 brought alpha.34 and alpha.35 (12 upstream commits
  after `47eabd41`). Two conflicts, both in `Map`'s native API: upstream removed the
  `LPTSTR`-keyed `SetItem` overloads and added `ValidateKey`, a `ResultToken`
  `SetItem` and a new `SetItems` signature. The fork keeps one `SetItem(LPTSTR,
  ExprTokenType&)` overload for `json.cpp` and keeps named temporaries where
  upstream binds `ExprTokenType(...)` to a non-const reference (an MSVC extension
  GCC rejects; the mingw CI target builds this fork).
- The engine now identifies as `2.1-alpha.35+Console`. `Print`, `Eval`, `JSON`,
  `Inspect`, `ProcessPipe`, `Check` and `TSParse` are unchanged.
- `JSON.Parse` with `Container: "Map"` keeps working: it stores keys as strings
  through the fork's `SetItem` overload, which `ValidateKey` does not touch.
- Verified on the MSVC x64 build: console gate 17/17 suites, `tools/check_all.py`
  104/104, `qa/tests/test_print.ahk` 9/9, and the new `qa/tests/test_alpha35.ahk`,
  which pins the `Map`/`Array` type checks, `Enumerable: false`, the v2.1 `<A_B>`
  lookup, `AhkLibPath` and `Print`.
